# 去审查（abliterated）模型的选型与评测

适用：主人要「无审查版」跑危险代码审查、角色扮演、创作等。或有人声称某去审查版「无损/更强」。底座是非特化开源模型（Qwen 系、GLM、Gemma、gpt-oss）靠后训练移除拒绝行为。

## 先分清两种「无审查」

- **数据集过滤（Dolphin 路线）**：微调前把拒绝/回避样本从训练集剔掉，模型从没学会拒绝。
- **去审查（abliteration）**：从已对齐模型里把「拒绝方向」从权重中正交化移除，不重训。
- 不少模型是两者叠加，还叠了社区微调/合并——**叠得越多越难归因**，评估前先拆清有几层改动。

## 指标纪律（这一类专有）

1. **原始 GSM8K 分数会骗人，必须报「修正分」。** 思考模型（Qwen3.x、GLM-4.7 等）被去审查后常「想太久」，把思考预算耗光、不输出正文，被记 0 分。**测量时把「空回答」与「答错」分开报**：剔除空回答后再比，各变体实际数学能力差往往只有几个百分点。而原始分行距能到几十点。
2. **空回答率 = 去审查激进度**。改得越宽越容易陷入思考循环。空回答率高 = 做 agent / 代码审查很难受，即使榜面分数好看。
3. **KL 散度是最诚实的能力指标**（相对原版的输出分布漂移，越低越好）。能力基准（MMLU/HellaSwag/ARC）几乎不动 ±0.5 分。**TruthfulQA 普遍掉 5–11 分**。GSM8K 第一个崩——但先按第 1 条修正再看。
4. **技术排序：手术式 > 粗暴式**。同底座上，改动张量少而精的（Heretic 系、ARA、条件式）保留最好。改得最多的（大锤式全张量）常落榜末且推理退化。「改得最彻底」不是优点。
5. **「无损 / 100% 保留 / 能力增强」一律当作待验证的声称。** 独立取证多次证伪过这类口号（含一个被广泛转发的模型族，其工具被查出是抄袭 fork、声称造假）。验证方法见 open-weight-forensics skill。

## MoE 专属要点

- **MoE 去审查必须做「专家粒度」（EGA）**：只按稠密手法（改注意力/MLP 输出投影）去审查。专家里的拒绝信号去不掉——实测稠密手法留 ~29/100 拒绝，加 EGA 才降到 ~3/100。
- **MoE 对去审查的耐受度高于稠密**：同底座四技术实测全部 100% 去审查成功，能力大多在 1% 内。
- **去了安全 ≠ 不想**：部分模型去审查后，CoT 里仍能看到「这有害吗」的推理、只是照做。这会消耗思考预算（联动第 1 条）。

## 榜单来源

- **UGI Leaderboard**：唯一为这一类建的榜（UGI 分数 = 敏感话题知识广度。W/10 = 意愿。NatInt = 自然智能）。LM Arena 无去审查赛道，不适合评这类模型。
- **Abliterlitics**（abliterlitics.dev）：同底座横比各技术，KL + HarmBench + 任务套件，当前最硬的量化对照来源。
- 中文社区下载榜只作热度参考，**不等于能力**——高下载量常来自「门槛低 + 去审查彻底」，与质量无关。

## 落地顺序

先按用途分流：**代码/安全向**要「能力 + 合规」平衡。**角色扮演/创作**要文笔与人设稳定性。两类最优常不是同一个模型（例：工具调用强的 OpenAI 血统模型 RP 差，写作模型编码弱）。选定后再按 SKILL.md 的 MoE 卸载 recipe 落实命令与量化档。
