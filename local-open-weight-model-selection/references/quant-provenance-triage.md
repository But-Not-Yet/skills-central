# 第三方量化卡 / 仓库的可信度分诊

适用：主人在 HF 上看到一个量化仓库问「这个如何」。要判的不是分数高低，而是三件事：**能不能拿、数字能不能信、缺的那块能不能补**。

## 0. 先钉物理事实，再读口才

- **门控**：`curl -s https://huggingface.co/api/models/<repo>` 看 `gated` 字段。权重可达性用 resolve URL 的 HTTP 状态码实测（200 可取 / 401 需登录接受条款）。**README 可读 ≠ 权重可下**——门控仓的 README 与 API 元数据都是公开的。
- **体量与关注度**：`downloads` / `likes` / `lastModified`。下载量是「被别人踩过」的代理，不是质量证明。千级下载意味着几乎无人复核，百万级才谈得上社区筛过一遍。
- **仓库完整度**：只放 gguf + README 的仓 vs 附带 `SHA256SUMS.txt` / 逐张量分配表 / imatrix / tokenizer / chat template / mmproj 的仓。后者可核对、可复现。前者出错无从查起。

## 1. 数字口径三问

1. **有没有同尺寸标准量化的对照？** 只跟自己 BF16 比 PPL/KLD 的卡，回答不了「这个量化比标准档更好还是更差」。有同尺寸对照档（如 UD 系）才算可读。
2. **基准分辨率够不够？** 30 题的小集（AIME25 这类）一题 = 3.33 分，「精确持平」是一格分辨率的事。零样本 recovery 出现 >100% 说明该指标已在噪声级。小样本上的「task-lossless」只能读成「在基准分辨率内看不出差别」，不能当绝对无损。
3. **测没测你最在乎的能力？** PPL / WikiText / 零样本知识题**不能替代**工具调用或 agentic 基准。对 agent 用途，卡上没有工具调用（尤其近失率）数据 = 这个问题没被回答，保真数字再漂亮也是空的。

## 2. 血统与对比对象陷阱

- **底座是审查版还是去审查版**要看模型树的 base_model 一行：去审查需求下拿官方 base 的量化等于白拿。
- **「胜过 X」的对比对象可能是同作者的另一条血脉**（例：同一作者对两种 abliteration 血统各发一版，卡里的横比只覆盖其中一版）。用别人的对比结论前，先确认被对比的正是你在看的那张卡。
- **方法披露程度 = 可复现性**：有论文 + 公开代码 + 逐张量分配表 = 可审计。「proprietary / 校准与方法不披露」= 只能当宣称，哪怕指标漂亮。
- 营销词（Cyber / Turbo / Heretic 等）**不代表能力**：真正的后训练能力常在另一个闭源/申请制模型里。你手里的文件只是 base 的量化。
- 别漏掉「反直觉的诚实」这类加分信号：调参方劝你上更高量化、或主动公布失败与上限。抬高的是自己的运行门槛、没有销售动机。

## 3. 可复现的社区转移 recipe（公开分配表 → 本地去审查 BF16）

逐张量分配表（GSQ-RCO 类）可 1:1 转移到**同架构**的 BF16 权重，无需重跑搜索：

```
llama-quantize --imatrix <官方.imatrix> \
  --tensor-type-file <allocation-table.txt> \
  <base-bf16.gguf> <out.gguf>
```

- 分配表格式多为 `tensor_name=ggml_type` 一行一张量（常随量化仓一起发布）。
- 推论：**「去审查 + 公开分配表量化」的组合可以自己造**，不必等成品——拿去审查 BF16 底座 + 官方分配表。一条命令出档。
- 前提是同架构同张量形状。跨架构（层数/头数不同）不成立。

## 4. 卡上缺数据时的补救

- 缺工具调用数据就自己当闸：拉进本机 A/B 臂，判据先冻结（近失率、返工轮数、墙钟、token），再谈通过。
- 作者若点名了失败案例（哪个 case 挂了、哪个配置退化），那比总分更有用——记下来，作为本机验证的起点。
- 卡上的速度数字先看清**测量硬件与后端**：CUDA/vLLM 上的数不能直接搬到 ROCm/其它引擎。标着「derived」的行是推算，验不了。
