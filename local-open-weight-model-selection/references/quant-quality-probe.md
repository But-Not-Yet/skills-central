# 同底座量化档的质量对比评测

适用：同一底座不同量化档/不同量化器（APEX、NVFP4、mradermacher i1、官方 GGUF 阶梯）之间要比较「质量掉没掉」。速度对比见 SKILL.md 的卸载 recipe。

## 铁律：先验证判分环境，再测模型

**拿一个已知正确的输入跑一遍判分链，它必须给出已知结果；否则后面所有分数都是废数。** 基准自带金标（gold patch / gold answer）时就用它：

- 失败路径：未修的状态下目标测试必须**失败**。
- 成功路径：打上金标后目标测试必须**通过**。
- 两条都对，判分环境才成立。只验成功路径不够——一个「恒通过」的判分器也会全绿。

先拿 1 题探路，再全量扫一遍看**哪些题的环境真能立起来**。环境立不起来的题必须剔除，不得混进分数。

## 判分器本身也是被测对象

- **喂合成输出自测判分逻辑**：对每个题型构造「该过」与「该挂」的例子，断言判分器的输出。反例（像差一字符、大小写、标点）一定要包含。
- **手写答案键必须自己先解一遍**——逻辑/数学题的 key 写错会让正确模型被判失败，而这种错只有自己推一遍才看得出。
- **归一化要穷举模型的合法写法**：下标/上标数字（`H₂O` vs `H2O`）、全角符号、千分位逗号、中英文标点。少一个就产生假失败。

## 题面设计：避开天花板与地板

- **目标模型考 95%+ 的题库区分不了两个量化档**——两者都满分，等于白测。量化损伤只在**能力边缘**显现。往失效边缘推：大数长链运算、多重约束指令、长尾知识、多针长上下文检索、精确计数。
- 反方向同样危险：**太难 → 双双 0 分，从天花板效应变成地板效应**。
- **优先用真实基准原题，不自己造题**。自造题只能证明「模型能做我的题」，原题才有可引用的说服力。

## 协议不同 = 不可比（硬规则）

- **同一张表内的列可以横向比；跨来源拼起来的数字不可以。** 每家自己的官方表用了不同 harness、不同 n-shot、不同采样，拼在一起不是排名。
- **能拿来比的表**：同一张官方对照表里同时列了双方（同一批题、同一 harness）。即使发布方是竞争者，同表对照也比拼表强得多——但要标注「由竞争方测量」。
- **同一分数在不同协议下意义不同**：对数似然评分 vs 生成式再解析（有 parse failures 就是后者）、全量测试集 vs 子集（题数对不上就是子集）、有/无思考模式——这些都必须连着分一起报。
- **聚合前核对列**：多列对照表里每一列是一个不同型号。拿家族中位数/均值当某具体型号的数字报出去，会把型号 A 的成绩安到型号 B 上，而且数值看着完全合理、不报错。**报具体型号就取它自己那一列。**

## 可复现的执行协议

- `temperature=0` + `top_k=1`；每题独立请求；`cache_prompt=false`（否则命中缓存的那题不再冷）。
- **关掉思考模式**做质量分（要的是答案不是推理过程），或把 `max_tokens` 给足以免思考吃光预算——**思考模式把 max_tokens 吃光时 `content` 为空**，看起来像模型不会答，其实是没吐完。
- 强制一个可解析的终止标记（如 `FINAL: <答案>`），解析时**取最后一次出现**（正文里可能提到这个格式）。
- **`content` 空时回落到 `reasoning_content`** 再判，别直接记 0。

## 在无 Docker 的机器上跑真实代码基准

- **先查基础设施**：`docker` / `git` / 磁盘余量。**Terminal-Bench 必须有 Docker**（harness 连的是沙箱化终端），没有就直接判死，别搭半天。
- **选纯 Python、依赖少、单文件测试秒级的仓库子集**（sympy 550 题池够用；Django 占大头的仓库群单题测试要跑几分钟，不适合当快速探针）。**整池只克隆一个仓库**，省下每个仓库的搭建成本。
- 单题流程：`git checkout -f <base_commit>` → `git apply <test_patch>` → 跑 `FAIL_TO_PASS`（**应失败**）→ `git apply <gold patch>`（**应通过**）→ 重置。**用部分克隆**（`git clone --filter=blob:none`）省流量，blob 按需拉取。
- **旧题需要旧 Python**：`collections.Mapping` 在 3.10 移除、`distutils` 在 3.12 移除。无 Docker 拿不到 per-repo 镜像时，用一个 `sitecustomize.py` 把 `collections.<ABC>` 别名补回（从 `collections.abc` 映射），`distutils` 靠 `pip install setuptools` 注入。这比装多个老版本 Python 便宜得多。
- **模型侧协议**：裸聊天接口（没有 agent loop）跑不了标准 SWE 流程。退而求其次：**给题面 + 金标改动涉及的文件当前内容**（只列文件名，**不给金标内容**）→ 让模型输出 unified diff → 应用 → 跑测试。
- **`git apply` 要三级容错**：`git apply` → `--3way` → `-C1`。模型产出的 diff 行号常不准，直接失败会让分数虚低。
- **注意地板效应风险**：一次性 patch 协议很难，两个量化档都考 0 就白测。先拿目标模型试跑 5 题，全 0 就换协议（加文件提示、降难度、或改判据）。

## 在 Windows 笔记本上部署与运行

- **远端命令静默返回空（退出码 0、无任何输出）≠ 远端没有那个文件。** 先探连通性再怀疑内容：ssh config 里的 `HostName` 可能指向当前不可达的网络（VPN 地址与 LAN 地址会随主人在哪边而化反，注释里的「某地址已失效」也会过期）。用显式地址各探一次（`ssh -o ConnectTimeout=8 -o IdentitiesOnly=yes -i <key> User@<addr> hostname`），通了再往下查。**不要改主人的 ssh config**（两边都可能要用），用会话内封装脚本固定当前可达地址。连续三条空输出还继续当「文件不存在」查 = 白烧时间。
- **传文件用 `scp`，不要用「base64 塞进命令行」**。经 PowerShell 的 base64 传文件在超过 **Windows 命令行上限 8191 字符**（约 6 KB 源文件）时**静默失败**；命令后再接 `>/dev/null 2>&1` 就连报错都看不见。症状是传了两次都「成功」，远端还是旧版。
- **传完双向对哈希**（本地 `sha256sum` vs 远端 `Get-FileHash -Algorithm SHA256`），别信返回值。要「改动生效」时先验版本特征（`Select-String -Pattern '<新加的字符串>' -SimpleMatch | Measure-Object`）再跑。
- **别用内联 `python -c "..."`**：ssh → cmd → python 三层引号会被逐层吃掉。写脚本文件传过去再跑。
- **stdout 编码**：中文 Windows 控制台是 GBK，Python 打 UTF-8 会 `UnicodeEncodeError` 崩在 print 上（常崩在收尾打印，看着像逻辑错）。跑前设 `PYTHONIOENCODING=utf-8`（PowerShell：`$env:PYTHONIOENCODING='utf-8'; & python ...`），脚本里也别用 emoji。
- **跑完读实机占用验分配**：`nvidia-smi --query-gpu=memory.used,memory.total --format=csv` 看权重上卡多少，配 `Get-Process llama-server | WorkingSet64` 看落内存多少。`--fit-target <MiB>` 的意图就是「留这么多空闲」，所以显存占用接近满才是对的。
