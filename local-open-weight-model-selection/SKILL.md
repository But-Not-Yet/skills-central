# 本地开源模型选型（消费级硬件）

## 何时使用

主人问「本地跑哪个开源模型」「我这台机器能跑什么」「这个量级最强的 MoE」「笔记本能不能利用起来」时。本技能管**选型与落地方案**；下载/量化/HF 仓库操作查 llama-cpp skill。主人要「去审查/无审查版」跑代码审查、角色扮演、创作时同样走本技能，评测纪律见 `references/uncensored-model-eval.md`。

## 第 0 步：先钉死硬件，不许猜

选型的一切推算从硬件开始，缺参数就先补：显存容量、系统内存容量、系统与加速后端、可用卸载池。主人的机器参数在 memory（先读）；memory 里没有就查会话史或直接问，绝不凭印象假设。

## 内存铁律（一切推算的起点）

- **总参 → 内存占用；激活参 → 速度。** MoE 每 token 只激活一小部分专家，但**全部权重都要装进内存**。一个 1T 总参、激活 30B 的 MoE 仍是服务器模型。
- 可用池 = 显存 + 可卸载内存（llama.cpp 能把路由专家甩给系统内存）。判定「能不能跑」的标准是：**权重 + KV 缓存 ≤ 池**。
- 别被小激活数骗：激活小只说明快，不说明装得下。
- **卸载不是万能的：稠密模型部分卸载 = 死路，显存装不下时必须落到 MoE。** 稠密模型每个 token 都要把卸载到系统内存的那部分权重**整个读一遍**（卸载 6–8 GB → 每 token 读 6–8 GB），内存带宽直接吃满，速度塌到不可用；MoE 每 token 只读激活的少数专家（约 1 GB/token 量级），差一个数量级。**「权重 + KV ≤ 池」是必要不充分条件——它只证明装得下，不证明跑得动。** 绝不许把装不进显存的稠密大模型写成「可卸载跑」。

## 中文能力加权（主人偏好，硬性）

主人主要用中文发命令，选型必须给中文能力加权：

- **中文原生系（Qwen 家族）在纯中文任务上稳赢非中文特化的开源模型。** 拿非中文模型当主人主力时，必须明说这一层差异。
- 评估来源：中文社区（CSDN、知乎、掘金、博客园）的评价与踩坑密度，权重不低于英文榜单；**教程密度本身是选型成本的一部分**（对主人调试更省事）。
- 非中文模型的已知中文画像（以 Gemma 系为例）：理解可用、能抓反讽；生成偏翻译腔/书面，网络用语与文化梗弱；强项在中英混合与用中文做推理。

## 时效核查（每次必做）

模型版图按季翻新，禁止拿旧知识硬答。开口前先查当前代际，并注意两种「看似最新其实不是」：

- **代际跳档**：某一代可能整段跳过中间档位，此时上一代的中档才是当前最新的中档 MoE——先核当前栈再推。
- **架构混淆**：同名数字可能是稠密而非 MoE。稠密每 token 全参走一遍，内存与速度都是另一套算法；选型前先确认架构。

## 给命令，不给名字

选型结论必须落到**一条可执行的 llama.cpp 命令 + 量化档 + 预期速度**，而不是只报模型名。主人要的是能直接跑的东西。

## MoE 专家卸载 recipe（llama.cpp，消费级单卡）

```
llama-server -m <model>-Q4_K_M.gguf -c 32768 -ngl 999 -fa on \
  -ot "exps=CPU" -b 4096 -ub 4096 --parallel 1
```

- `-ot "exps=CPU"`：路由专家进内存；注意力 + 稠密 FFN + 共享专家留 GPU（等价 `--n-cpu-moe`，注意它从最高编号层数起）。
- `-b 4096 -ub 4096`：把提示词处理批全压给 GPU，长提示才不卡（默认批太小）。
- `--parallel 1`：单用户必设，否则上下文被切 N 份，长文直接超限。
- 起手后逐档加 `--n-cpu-moe N` 把专家挪回显存，试到显存刚好占满 = 速度甜点。
- **速度预期按「多少权重留在内存」估，别按激活参数乐观。** 大部分权重在 DDR5 上时落到个位数到十几 tok/s 是常态；当 agent 后端偏慢，当写作助手够用。
- **先读懂主人现有的启动脚本，再决定要不要自己算。** 新版 llama.cpp 有 `--fit on --fit-target <MiB>`：**运行时自己按显存预算分配专家层**，走这条路时命令行里不该再出现 `--n-cpu-moe`——两者语义重叠，手写值会和自动分配打架。主人线上脚本若已是 `--fit`，头部推算的用途就只剩**预测与复核**，不是要写进命令行的参数。**先 `type` 出他现在的脚本读一遍再动手**，否则整轮推算可能白做。
- **别猜 `--n-cpu-moe`，读 GGUF 头部算。** 现成脚本 `scripts/gguf_split.py <path.gguf>`（本机直接读；远端先 Range 取前 ~32 MB 落盘再喂）。原理：tensor_info 里每个张量带 `offset`，按 offset 排序后**相邻差值就是该张量的字节数**（无需解析 ggml 类型表），末位用「文件大小 − 末位 offset」兜底。据此把专家张量与非专家张量分开。**非专家（注意力/嵌入/共享专家/范数）必须常驻显存，它才是显存预算的大头**；专家才可卸载。**量化档换一档，拆分就变一次，必须重读**——同一底座不同导出管线的非专家占比能差 3 倍（实测：Experts-Only 型保留高精度非专家 → 非专家 4.68 GiB；全量化型 → 1.53 GiB，同为 ~15–23 GiB 文件）。仍属**推算**，llama.cpp 自身运行时开销算不到，落地后留 ±2 的微调余量（OOM 就加、想快就减）。

## MTP（自带投机解码）别浪费

Qwen3.5/3.6 系的 MoE **自带 MTP 头**（草拟下几个 token、主模型一次前向验证），llama.cpp 用 `--spec-type draft-mtp`（可配 `--spec-draft-n-max`）启用，**无需外挂 draft 模型**。

- **对卸载场景尤其值钱**：专家卸载把机器变成**解码瓶颈**（每 token 都要从内存流权重），prefill 提速帮不上，只有打 decode 的手段有用——MTP 正是打 decode 的。
- **选文件时确认「MTP 还在」**：NVFP4/GPTQ 等转换**常把 MTP 头丢掉**（丢头后 draft 接受率归零）。仓名带 `Native-MTP-Preserved` 的才是保住的；同名仓的 MTP 版与非 MTP 版**体积差通常只 1–2 GiB，没理由省**。
- 别用「体积小一点」当选非 MTP 版的理由——这是小喵实测犯过的错。

## 许可与风险标注

- Apache 2.0 / MIT 优先于自定义社区协议（商用与再分发更干净）。
- 一个模型被点名「坏权重 / 训练 bug」时，**发现与归因分开陈述**（见 mechanism-claim-discipline）。
