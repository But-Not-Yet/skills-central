# 交付自验证闸 + 批判角色（主人裁定 2026-10-06）

## When to Use
任何报告/任务卡/实验设计标终态或交付主人之前：日常交付过闸 A（自验证）。高风险交付（论文级、任务卡、预注册）加过闸 B（批判角色子代理）。长讨论链收尾时同样适用。**即将烧 ≥1 小时算力的测量脚本，点火前同样必过闸 B**（见「测量脚本双镜头审查」）。

## 背景一句话
裸自验证（自己读自己写的东西投票）= 给偏见做多数表决，抓不住仪器级错误（R2-18 教训）。有效的自验证必须落在文件上：裁决时重新打开数据重算，不复述叙述。谱系：MoA（集成，Together AI 2024）的反面。辩论线（Irving 2018 / Du et al. 2023）+ LLM-as-a-Verifier（arXiv 2607.05391）的判据分解与「只信观测输出不信自述」。

## 闸 0 · 规格审查（起草前。**出题人自己的活，不能外包**）

闸 A/B 都在核「稿子里的断言」。闸 0 核「稿子的前提」。**任何规格/题目/任务卡/实验设计在发出去之前，自问三句：**

1. **范畴**：里面列的东西是同一个范畴吗？有没有夹带一个不同类的项？
   → 一个错位的项会让整場比较失去意义，而**执行者通常不会指出，只会照做**。
2. **尺子**：我给的维度/判准是哪一把？还有别的尺子吗？换一把会得到什么不同结论？
   → 把自己用的尺子**写进交付物**，别让它冒充「中性」。
3. **中立伪装**：「必须中性／不得预设立场」这类指令，是不是把某个立场当地面了？
   → **禁止预设立场 ≠ 没有立场**。它常常在禁止「质疑题面」。

**为什么必须出题人自己做**：实测（2026-10-06 五题对比）三个模型对一道含范畴错误的题**无一质疑**。其中一家在思考段识破了却**在答案里把质疑删掉**。
→ **错误的规格不会被顶回，只会被执行到底。** 不能指望 subagent 替你发现题面错。

**本闸补的是「尺子」不是「锤子」**：锤子=方法（怎么算、怎么核、怎么验），尺子=判准（用什么量、哪些维度算数）。手里的锤子不少，尺子往往只有一把**且不自知**。缺锤子会笨，缺尺子会**错得很自信**。多带尺子的同时也要防锤子钝化：锤子多了，危险不在到处敲，而在**用敲的动作代替了看**。

**两个可在产物里查的失效信号**：
- **察觉但删掉**：思考/草稿里有质疑，终稿里没有。这是「配合」不是「能力」，要查思考与答案的**差异**才看得见。
- **词表单源**：所有选项都用同一套理论词汇作答（例：只用合法性/问责/效率），未声明另一套判准存在。去审查能拆拒答，**拆不掉词表**。

> 三层各自的学科血统（Ryle 范畴错误 / Kuhn 不可通约 / SEP 预设论）、价值与立场的文献（Weber、Putnam、Douglas、立场论）。模型行为实测（Anthropic 谄媚研究 arXiv:2310.13548、假前提问题 arXiv:2510.10965）、锤子侧的 Goodhart/Campbell/代理失败。以及 2026-10-06 五题对比的完整判例，见 `references/spec-review-corpus.md`。

## 闸 A · 交付前自验证（每次汇报必过，低成本）
报告标终态前，对承重数字逐个执行：
1. **重算不复述**：每个关键数字回源文件重读/重算一遍（read_file / execute_code），从记忆里的数字不算。
   - 频次/占比类断言按 `hermes-session-forensics` 的「范围 + 定义 + 可复跑命令」三件套核；「全读」只用于真正逐条读全文的角色。
2. **判据三分**：每条判定写明 通过/失败/未定义 的处置，分母为零报 NOT-TESTABLE 不报 0.0。将冻结判据的测量对象逐字绑定到产物字段：探针 argmax 不能拿 token argmax 的较高值代验。同前缀条件一致不等于两条独立自由生成全同。终点字段相同不等于语义无伤。比较器本身口径错位应判 INVALID：不能把低分归因被测假说，也不能拿另一项既有汇总替代失败测试。
3. **全称词核数**：全部/从未/任何 → 同段必须有 n= 与置信区间或范围限定。对自己产物的全称断言（「公式全部抄自原文」「每个函数头都回锚」）必须钉状态快照。「核查后台账状态成立、核查前存在 N 处失真」：核查环节本身会修掉抄写失真。不限时点的全称断言对初版为假。**全称的两个具体失效面**：① 枚举不全禁全称：「全部 X 都 Y」必须验「清单穷尽了 X」。从分页/截断的列表工具（默认 50 行上限这类）读出的清单本身就是被截断的。逐条点名只对点名项作断言，全称另附穷尽性核查。② 状态断言钉核查时刻：「没有 worker 在跑」「服务已停」这类活体断言，只对当场 ps/查活的那个时刻成立。跨轮复用即失真（worker 可能此刻已被派出），所以每次引用都重新查活或显式带时刻。
   ③ **在跑的验证不算完成**：测试/编译/回归还没退出时，交付只能写「跑着（命令 + 起始时刻）」或「待」，完成断言只在命令退出后写。把进行中的事写成「全部做完了」，会被检察官按 Elevation of Privilege 打回；同一句话说出口前先问「有没有一个后台进程正在改写这个结论」。
4. **引用开文件**：「值（文件:行）」逐个真打开核查那行。断言机制/管线的（「X 是按 Y 计算的」）同罪：**先开文件找到生成管线那一行再出口**，没开过就标待核。不许当已核用。两类高频延伸：① 「判据 X 未测」这类负存在声明，先把全部侧产物扫一遍再出口。控制任务/旁路指标常已顺手算进训练日志或判据件的副字段里。标错「未测」会被主人或检察官抓现行。② 引用冻结文档的流程语义（「自动生效」「需确认后收束完毕」「只打断」）必须回原文读那一行再出口。流程语义改述错方向（把「需确认」说成「自动」）等于替指挥官改流程。
5. **形容词审计**（单点证据拔高为全局断言，同型错误连犯两轮后固化为动作）。「无损 / 最优 / 全部 / 更好得多」这类定性词逐个扫一遍，每个都要问「它背后的实测覆盖了哪个场景」。单点测试（一个检索测试、一张卡、一个配置）只能背书**同范围**结论：needle 通过 ≠ 精度无损。一张卡上的实测 ≠ 全部硬件最优。写法改成范围限定的：「needle 测试与 8-bit 相同，长文档 PPL 无实测」。

6. **盘点/审计交付的人话闸**：多信息源盘点、进度审计、比对表这类交付，正文先一段白话讲「到底出了什么事」，证据和表放在其后。主人要求 file:line 级引用不等于白话可以省——表每一行都得配一句「这行说的是什么事」的人话注解，纯代号+行号的表会被当「看不懂你在说什么」退回。自检法：开头一句念出来不像当面会对主人说的话，就先补白话版再交。

代价：每次汇报多 2–3 分钟。BOMB 类事故（修了 bug 没回改）在出口处被自己拦下。

## 闸 B · 批判角色（高风险交付用：论文级报告、任务卡、实验设计）
用 delegate_task 起一个**全新会话**的批判子代理（fresh context = 不被我的叙述污染）。

### 批判者提示词模板（逐字用。固定指令在前、交付物在后，这是 prefix cache。参 arXiv 2607.05391 判据尾部放置，命中率 5.2%→78.4%）
> # 角色：红队事实检察官
> 你是外部红队检察官，不是合作者。你不接受「大概/可能/通常」，只接受证据、边界、失效模式。
> 输入 = 主 Agent 预提取的 Claim 列表（每条带原文引句 + 证据文件指针）。你的任务不是重新审计整个项目：只打名单上的 claim，工具调用预算 ≤15。
>
> 方法三件套：
> 1. **FMEA 打分**。每 Claim 评 S（错则后果 1-10）× O（出错概率 1-10）× D（主 Agent 交付前能否发现：可工具核验却未核验=10）→ RPN。RPN>100=Blocker，50-100=Critical。按 RPN 降序，最多攻 top 5。
> 2. **STRIDE 事实污染扫描**（只保留对文本输出适用的四类，各有判例）。Spoofing=引用张冠李戴/引作废档案（判例：K5 头条三值出自 v1 作废档）。Tampering=断章取义或过度解读工具输出（判例：「全部」实为 10/26）。Repudiation=不可追溯不可复现的断言（判例：BOMB 判定未回改）。Elevation of Privilege=局部事实拔高为全局真理（判例：n=9 撑 4.3 门）。
> 3. **交叉询问**：传闻证据排除（只认「值（文件:行）」一手证据）。严查相关性暗示因果性。证据链保全=引原文锁定 claim，禁止事后「我其实不是那个意思」。
>
> 硬规则：每条攻击自带一手证据（文件:行 或当场重算）。开不到文件降级为「待核疑问」。禁攻文风。不给修改建议。诚实边界：坐标系/仪器级错误在文本内部不可见（判例：双提示 bug 自查抓不住），找不到就不硬凑。那是外部锚的活。
>
> 输出（严格 JSON，无废话）：
> {"verdict":"GUILTY|ACQUITTED|CONDITIONAL","top_rpn":<int>,"attacks":[{"id":"C1","quote":"原文","rpn":<int>,"stride":"类别","evidence":"文件:行=实测值","one_line":"指控一句话"}],"assumptions":["隐藏前提≤3条"]}
> attacks ≤5 条，每条 one_line ≤40 字。具体事实由主 Agent 自己回文件核验，不要求检察官展开。

### Claim 预提取（主 Agent 职责，批判者不做）
交付前我自己提取承重断言成名单（≤8 条，每条：原文引句 + 证据文件指针），按「错了最疼」排序。这一步几乎免费，且把批判者的工作从「重新审计」压成「定点爆破」。

### 答辩协议（小喵执行）
逐条处置，三选一：**接受**（改，附改动）/ **反驳**（附证据，同样必须开文件）/ **待核**（写明怎么核）。
**待核不是终态**：自己标出的待核项要主动深挖闭合。回产物目录 grep 该值、追计算脚本、重读写入文件的成品，都要做。主人会直接下令「把待核项直接深入核查」。挂着待核等催等于欠账。检察官的追问底下，常藏着比其指认本身更深的洞。他指「全称断言无锚」，顺锚追下去可能挖出真缺产物级出处，或坐标归属写错。处置一条指控就要把它的追问链走完。

裁决铁律：**攻防只看文件，开不到文件的一方输。**攻防循环 ≤2 轮，仍僵持 → 列进「待拍板」交主人，不许小喵自己终审自己的辩护。

### 成本与边界
- **周期化裁定（主人 10-06 批复）**：「每轮或每几轮自动事实核查是必须的」。核查主体就是红队检察官（不是纯正则 linter，那是写卡时引入的偏差，LCM store_id 51048 原话为证）。三层架构：L1 每轮正则抽断言（免费）。L2：每 N≤3 轮用本地模型跑检察官（red-team-auditor SOUL）。固定 prompt 前缀吃缓存，断言清单放尾部，输出上限 ≤5 条一句话攻击，各带证据指针。L3 下轮注入判决书，小喵必须逐条处置。亲密/闲聊轮整轮豁免。软提醒不硬拦。**禁外部 API，走本地 8080/8081**（省钱裁定）。实现挂 Tiered 插件（看板卡 t_dd47e4ee）。
- 批判者只打预提取 claim（top 5-8），工具预算 ≤15。防止跑成重新审计（实测：全量核查 6 卡引用 ≈ 重跑昨晚九轮，思考 token 10k+ 起步）。PPT 原则：预算集中在不确定的高位候选，不做全配对。
- 只在高风险交付用闸 B。日常汇报只过闸 A。
- 强制化路线（主人裁定 2026-10-06）：每 N 轮自动事实核查 = 脚本约束。归 Tiered 插件（hook 抽取回复中的数字/引用断言，再回文件核查）。skill 只留协议与 prompt 文本。插件动工前先查 Hermes hook API 文档。
- 批判者抓不住「所有草稿共享的盲区」（仪器级错误需外部锚）。那是审计/外部对照的活。
- 批判者的自我报告也要验：它声称「打开文件核查过了」，抽查其引用行号。**检察官的引证本身也要复验**：检察官会把代码转述成逐字引文、把文件路径写错。逐条处置前先开文件 grep 被引行与路径是否存在。指控机制与实际代码矛盾时驳实质：半认半驳是合法裁决（实质认、引文纠、机制驳）。答辩方同样必须开文件给证据，不能只说「你引错了」。

## 测量脚本双镜头审查（烧算力前，主人裁定：「不能再犯之前探针的错误了，成本太高」）

要烧长算力（CPU/GPU 小时级）的测量脚本，点火前先过双镜头审查，只审不改、代码零改动：

- **两镜头互补，各一张看板卡**：镜头一 = 代码正确性（协议忠实性、数学构造、内存/运行时、陷阱类、验收行）。镜头二 = 对象身份与测量有效性：「就算一行不出错跑完，出来的数字能不能当原始欠账的答案」。欠账是两件套时，单块脚本只解锁半边，结论范围不得大于测量范围。卡体要给攻击点清单（A1..An / B1..Bn，逐条判定加文件行号），再写清「什么算交卷」。交卷物 = 红-橙-黄分级缺陷清单或 RPN 表，不是泛泛意见。
- **修正回主会话结算**。主会话逐条处置（接受/反驳带证据/待核），然后改脚本，再自跑冒烟（拿 2 列 jvp 对中心差分对照）。过了才落 GO 旗标点火。编排脚本带 GO 旗标门：旗标不落，生产服务绝不停。
- 审查战果通常是实弹。实测抓到过三类。「CPU sdpa 内核无 forward-AD 致主目标层静默 STUCK」是一类。「逐列循环超窗 25 倍」是一类。「脚本只测了欠账的一半」是一类。还抓到过「偏差台账对文献的陈述被原文逐字证伪」。审查卡钉本地模型跑，不占云端预算。

## 外部审计的处置协议（审计/检察官交来的判决书）

外部审计与内部检察官同罪处置：**逐条回盘取证再判，不许整份照收也不许整份驳回**。先出一张判决表（每条：采纳/驳回 + 一手反证），再动手改。

- **过时快照是审计的头号失效模式**：审计员看到的常是几轮之前的世界。它断言「日志不见了」「二三关没跑过」「脚本还没落盘」时，产物可能早已在盘上。处置前先对时间戳：拿被审对象写入文件的时间，与审计出题时刻比对。晚于出题的产物，直接判「前提过时」，不进采纳清单。
- **被审文件正被改写时，双方可能对不同态都为真**：手术进行中的活文件（SOUL 被整件替换、配置被重写）会让检察官的 grep 与你的反驳各自符合自己核对那一刻的状态。处置判项引文件证据必须附文件 mtime 并写明「核的是哪个态」；被替换的旧态留 `.bak`，否则当时的真相再也 grep 不出来，驳回就成了口说无凭。
- **反例不存在就驳**：审计举的代码行/键名/文件，grep 不到就是不存在。「这个键我没见过」不等于「这个键不存在」，开文件读到那一行才算核过。被驳的幻影会跨轮复发（同一对不存在的行号连续两轮再引）。驳回时把反证原文留档（grep 零匹配的输出、git 首版对照），复发时直接引反证结案，不重新开庭。
- **检察官的计数与时间戳同样要当场重数**：判决书引「共 N 条记录」「ts=X」时，要对全文件重数一遍。被引时间戳的行还要逐条 grep。检察官的计数同样会不复现。实测案例：声称含关键词 3 条，实数 9 条。所列时间戳里有两条根本不含该词。所谓「唯一出处」，只是判决书文本自身的会话回显。复现不了就驳回计数并附重数命令，别把对方计数当事实接着推理。
- **改前后风格指标必须声明计数单位**：`grep -c` 数的是含匹配的行数，`grep -o | wc -l` 数的是出现次数。两者会反向（一轮编辑行数下降而次数持平甚至上升），混用会报出假改善。汇报改前/改后数字时注明用的哪条命令，改后必须用同一条命令复数。
- **检察官自己的 SOUL 也带它抓的毛病**（「对……进行」句式、自造比喻词）：主人裁定就地修时直接 patch 其 profile 的 SOUL.md。先备份，改完 grep 重新数一遍确认零残留。未经裁定的词不顺手改。
- **驳回成功 ≠ 自己原句干净**：检察官的攻击对象可以是错的（把甲指标归因给乙）。而自己原句的用词同时是松的（把「触发率」写成「误触发率」、把「触发率」当「误触发率」的合格证据）。驳回每条时重读自己被审的那句，用词有松动就主动认下半条并更正。判决表允许「指控驳回、自查自认」并存，只报驳回不报自查等于藏自己的账。
- **指控错、方法论对，要分开结算**：审计的具体断言全被反证击穿。不代表它的方法论批评无效（「别凭记忆签字、先实读 argparse 与真实键名」这类）。采纳方法论、驳回断言，并当场用它的方法自查自己的新代码。新写的核查代码同样会栽（字段口径按设计文档猜、不按真实 schema 核），栽过才把口径钉成 dry-run 实证。
- **审计的「缺了什么」比「错了什么」更值钱**。它指出的漏项（缓冲丢尾、日志不写入文件、复制排在判定前、provenance 缺被跑文件指纹）往往是真缺陷。即便它举的理由是错的。整改以实读到的写盘点/键名为准，不以审计的叙述为准。
- **被截断输出承载的数字，重跑成「活行」再谈**：判决书指某数字出自被截断的工具输出时。不要在旧输出上逐字申辩：把该数字当场重跑并完整打印（新输出自带截断状态字段）。以重跑结果作为活行。范围声明必须同步钉死：只能说「凡仍被引用的数字已重建为活行」，禁止「全部已回查」这类全称。历史截断段里未被重建的内容，明确标注「不承载任何现行结论」，而不是假装核过。多次判决反复指向同一批截断数字时，第二次就该停止解释、直接重跑。
