# 机制论断的取证纪律

**适用**：任何「X 是因为 Y」式的因果/机制论断——口头回答、报告的根因节、诊断结论、下一步建议都算。数字有 FROZEN 判据管着，机制没有；本技能补的就是这个缺口。遇到内部代号（S3-R、HP1 这类）先查 `~/Documents/Hermes/灵感笔记调研_20260929/framework/代号对照表.md`，对外输出时每个代号首现带白话括注（汇报纪律见 reporting-discipline-cn）。

## 四条硬规则

1. **定义优先于名称**。解释两个条件的差异之前，必须先读构造这两个条件的代码（或文档），逐字确认到底哪里不同。禁止从条件名字推差异（「训练风格 vs chat prompt」→ 就断定是格式差异 = 错）。自查句：「我读过定义这两边的源文件吗，第几行？」
2. **全量统计优先于样本轶事**。决定性统计量若在盘上数据里可算，就必须从全量数据算。手挑 N=3 的诊断脚本只能**提出**假说，不能**结论**假说。实测教训：710 行逐 token 数据在盘上，却用 3 行诊断输出写了整条根因链；补算全量 AUC 后结论反了。
3. **先跑反证再开口**。开口前自问「哪一个便宜的检查会让我错」；若该检查 <5 分钟且数据/代码已在手，先跑再答。反证成本极低时，不跑就是选择犯错。
4. **未验证的机制不起名字**。给未验证的机制起个短名（「病 A」「regime shift」）会让它听起来像诊断，之后被引用而不是被复检。必须起名时，名字里带「假说」字样。

## 报告写作信号

- 根因节标题里自辩（「非事后开脱」「已验证」）= 该节证据不足的信号。真有支撑的结论不需要在标题里辩护。
- 写「判决=FAIL」之前先答一句：「仪器在工作分布上读数可信吗，证据是什么」。答不出 = INVALID（仪器故障），不是 FAIL（假设不成立）。INVALID 不构成对假设的任何判决，必须修仪器后同判据重跑。
- 自己先前报告里写过的「边界标注」必须在新结论里被使用或显式推翻；写了不用 = 白写。

## 摘要不是上下文（硬规则，2026-10-04 主人裁定）

**永不相信压缩摘要。** LCM 摘要、会话弧摘要、d0/d1 节点、压缩后的上下文块——全部只是**定位工具**，用来帮你找到该去读哪个文件、哪个 session、哪个 node。它们不是上下文，不是证据，不是「已经读过」。

- 凡要引用摘要里的数字、引文、判据、状态、因果链：必须回原文读出。路径 = `lcm_expand`（当前会话 node）/ `lcm_load_session`（跨会话原文）/ `lcm_expand` 的 `store_id` 模式（跨会话单条）/ 直接 `read_file` 落盘文件 / 读源码。
- 摘要与原文冲突 → 以原文为准，且要在回答里说明冲突（说明冲突本身就是信息）。
- 原文取不到 → 标「未核验」，继续用则明说是「按摘要，未核」。
- **自己的旧输出经摘要回来，同样不算已核验。** 这是自我强化错误环：我写的 → 被压缩 → 我引用 → 看起来像外部事实。实测代价：连续两轮从摘要引用自己早先的机制断言，两轮都错，第三轮才去读代码。
- 压缩的系统性偏差方向是确定的：**剥限定语，留断言**。「仅末位、N=3、手挑样本、待核」会消失，「饱和、反号、根因是」会活到最后。所以摘要里的断言永远比原文里的说法更硬、更绝对——引用摘要 = 系统性高估自己当年的把握。
- 会话里的论断不继承报告的严谨等级。报告的闸门（FROZEN、脚本复算、排除条款）不会自动加到聊天回答上，必须手动加。
