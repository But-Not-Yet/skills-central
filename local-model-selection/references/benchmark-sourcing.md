# 基准数据的取用纪律

## 一、覆盖核验：不许凭记忆说「某站覆盖了某模型」

- 站点真实页面清单以 `sitemap.xml` 为准：`GET <site>/sitemap.xml`，正则取全部 `<loc>`，按 `/models/` 之类的路径过滤。
- 逐条探测候选 URL，看 200 / 404。**不要**因为「某站有 X 的页」就推断它有 X 的**某个具体变体**的页——同族常只测过其中一个（稠密 27B 有页，同名的 35B-A3B MoE 可能 404）。
- 断言「X 站有 Y 的取证基准」之前必须做这一步。凭印象说 = 瞎说，用户会当场抓，而且这类错会连带污染后面所有排序。

## 二、厂商自报 vs 第三方聚合：会给相反的名次，两边都可能是真的

- **厂商模型卡**：自选考纲。典型形状是只报对手没测的那几项，且全胜。
- **第三方聚合**（benchlm 一类）：把对手的全部公开行也算进分类分。
- 结果：同一对模型，「共享行」里 A 领先，聚合分类分里 B 领先。差异来源是**覆盖广度**，不是谁在说谎。
- 纪律：
  - 报数必标来源等级（厂商自报 / 第三方聚合 / 第三方实测）。
  - 解释名次背离时点明是「共享行」还是「覆盖广度」之差。
  - 实验室之外无人复现的能力表，标「未复现」，不许当已核验结论引用。

## 三、评测轴要匹配工作负载

- **HLE（Humanity's Last Exam）**：专家前沿知识。**「带工具」与「闭卷」是两个口径**——带工具考的是 agentic 管线，闭卷考模型本身。评测方自己声明：HLE 对日常任务（写作、商业分析、常规编码）**弱相关**，别拿它当 agentic 编码的代理。
- **agentic / 长周期编码** → Terminal-Bench、SWE-bench Verified/Pro/Multilingual、τ²-bench、Toolathlon、MCP-Atlas、DeepSWE。
- **工具调用可靠性** → 固定题集跑完成率（如 ToolCall-15），并记下能跑通的解析器配置；解析器不对时工具调用会以原始文本落进 content。
- **长上下文** → RULER / MRCR / NIAH 类，且必须与实际 KV 预算一起看。
- **去审查类目的统一尺** → UGI 榜（见 `uncensored-triage.md`）。

## 四、长周期 agentic 的可靠性四指标（比峰值分重要）

长跑 agent 会在循环里放大每个小毛病，所以除峰值分外必须查：

| 指标 | 为什么致命 |
|---|---|
| 超时 / 失败率 | 单轮挂起会卡住整个循环 |
| P95 响应时间 | 尾延迟决定循环能不能收敛 |
| 输出 token 膨胀 | 每轮多花数倍 token = 数倍等待与成本（实测有模型达舰队中位的 2.5×） |
| 逐次可重复性 | 同一文件两次跑落点不同 = 结果不可回归（实测有模型比对手差 3–4×） |

**峰值分高但有上述毛病的模型，在长周期任务里不如峰值分低但稳定的模型。**
附带查：输出契约遵守（语言/长度/格式冲突时会不会丢约束）——agent 管线依赖稳定输出契约。

## 五、禁止跨变体搬数字

- 同族同名的**稠密版**与 **MoE 版**是不同模型：张量结构、KV、专家布局都不一样。
- 一个变体的取证/基准数字**不能**给另一个背书。
- **微调/合并后的模型不继承底座的成绩。** 权重被 SFT 或 merge 改过（哪怕只合并 0.5 权重比例），跑出来的就是另一个模型。底座是官方基准表、而目标模型是它的微调版时，**底座的分数不是目标模型的分数**。卡里没有目标模型自己的数，就写「无数据 / 未核验」。
- 反过来，**「同一个协议下的 Δ」可以比**：同一张卡里「原版 vs 去审查版」的分差是同一批题、同一流程跑出来的，跨卡比这个 Δ 比跨卡比绝对分安全（但仍要注明各卡协议不同）。
- 自检句：我引用的这一行，跑的是哪个 checkpoint？和我在推荐的模型是同一个文件吗？

## 六、出来源，分栏写

- 结论 / 出处分栏。数字逐字给出，标明 repo、文件、张量或榜单行。
- 未复现的标「未验证」。**转述讨论区不算核验。**

## 七、比之前先验协议：同数不同尺 = 不可比

同一个基准名（MMLU、GPQA…）在不同卡里可能是**不同协议**，数字看着合理但不可比。指纹：

| 卡里的形状 | 协议 |
|---|---|
| 段落里有 `Parse failures: N`，逐科列 `(对/总)` | **生成式**：模型自己写出答案，再正则解析选项 |
| 表头有 `Version / Filter / n-shot / Metric / Stderr`，形如 `\|mmlu\|2\|none\|\|acc\|↑\|0.8372\|±\|0.0030\|` | **lm-eval-harness 对数似然**：给各选项打分取最高 |

- **可比的判据**：题数相同 **且** 解析失败的有无一致 → 同一协议，可直比。
- 生成式系统性偏低，跨协议排名会假性拉开。**跨协议只能各看各的，不许排名。**
- 一张卡里可能同时有两套测试（如 MMLU 7021 题 + PIQA 1838 题），别把两段的汇总数串起来归成一个。
- 题数只是**一半**于公开全集时也要标出来（卡里通常不写采样协议）。

## 八、优先找「同一张表列了两个模型」的源

跨源拼表是下策。上策是找**一张表同时给了 A 与 B 两列**的卡——同 harness、同一批题，争议最小。

- 这类对撞表的表头常是多模型横向对照（`['', 'A', 'B', 'C', …]`），混着同族不同尺寸与不同厂商。
- **判列**：表头归一化（去非字母数字、小写）后与目标模型名做**子串包含**匹配，取最长命中列；匹配不到才退第一列。取错列 = 整列数字换成别的模型，且数值看着完全合理、不报错。
- 读完后**必须抽 2–3 行回各厂商自家表对照**。若某列的值与厂商自家表逐项一致，说明那是转引而非重测——标出来。**同 harness 不等于独立复现；竞争对手当裁判这件事本身也要标。**
