# 远程 HuggingFace 权重取证

用途：核验「某张量尺度异常」「某版本就是上一代」「模型被训练坏了」这类断言，**不下载整包**，只取目标张量的字节。

## 原理

safetensors = 前 8 字节（小端 u64）给出 JSON 头长度 L；紧随 L 字节的 JSON 描述每个张量的 `dtype / shape / data_offsets`（相对数据区起点）。数据区起点 = `8 + L`。
→ 用 HTTP `Range` 头只取头部 + 目标张量区间即可。一个 64 KB 的张量只花一次几十 KB 的请求。

## 步骤

1. `GET https://huggingface.co/api/models/<repo>` 拿文件列表，找 `model.safetensors.index.json`。
2. GET 该 index.json → `weight_map` 给出每个张量在哪个分片。
3. 对用到的分片：Range 取 `0-7` 得 L，再 Range 取 `8..8+L-1` 得 JSON 头。
4. 目标张量绝对偏移 = `8 + L + data_offsets[0]`。
5. Range 取该区间 → 按 dtype 解码。
6. 算统计量（σ、均值、余弦相似度）。

现成脚本：`scripts/hf_tensor_stats.py`。

## 判断规则

- **同一模型内跨层比**：某层 σ 远超全层中位数时，先做**同层对照**——同层其他张量正常/偏小 = 局部异常；同层全都偏大 = 整体尺度上移。不区分就下「张量坏了」是过度断言。
- **系统性 vs 孤例**：把同族多个尺寸/版本全测一遍。**全族都有 → 是配方/架构的系统性现象，不是「某模型的随机损坏」。这一步最容易被跳过，也最能翻案。**
- **跨版本比**：同架构同层张量的余弦接近 1（如 0.9997）→ 是同一批权重上的一次轻量微调，不是两代新模型。逐类抽样（norm、bias、各类投影）看「哪些被改动、改了多少」，比单看一个张量有信息量。
- **别只凭权重统计下「好/坏」结论。** 统计异常 ≠ 能力受损；要断言能力必须另有受控评测（同底座、同评测集、同配置、跑前冻结判据）。

## 注意

- gated 仓库上 `api/models` 可能 401，未登录列不出文件。
- BF16 解码：`(u16.astype(np.uint32) << 16).view(np.float32)`。
- **一维张量（norm.weight、bias）多为 F32**，别按 BF16 解——会得到 inf/nan 并污染统计。先读头里的 dtype 再选解码器。
- llama.cpp 的内部张量名与 HF 不同名（例：HF 的 `linear_attn.conv1d.weight` 在 GGUF 里叫 `ssm_conv1d.weight`）。按名字搜不到时先列出该分片的张量名谱系再定位。
