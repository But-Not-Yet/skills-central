# 量化档质量探针（自建判分题库）

换量化格式后验「有没有掉质量」。速度从 `timings` 读得到，质量必须自己测——
**同底座换量化后 PP/TG 可以差数倍（见 SKILL.md 坑单），但快不等于没坏。**

适用：同一底座的两个量化文件（不同量化器 / 不同精度保留策略）互相对比，或换档前后回归。

**优先用真实基准原题，自建题库只当快速冒烟。** 用户明确不认自建题——要「原题」
（SWE-bench / Terminal-Bench 这类）。真实基准的搭建、判分环境探路与地板效应见
`code-patch-probe.md`；本文各节对两种探针同样适用。

## 1. 判分协议：先定死，再跑

协议里任何一项被静默改动，测的就不是同一个东西了。四条（**主人裁定**）：

| 项 | 规矩 | 为什么 |
|---|---|---|
| `temperature` / `top_k` | **一律不传**，用各模型自己的预设 | 强制 `temp=0`（或 `top_k=1`）测的是贪心解码，对真实使用场景没有意义 |
| reasoning | **必须开**（`chat_template_kwargs={"enable_thinking": true}`） | 推理模型关掉思考就换了被测对象。关思考的分数只能叫「no-think 分数」，不得当能力报 |
| `max_tokens` | **比回答质量时不设上限** | 上限制造的失败会伪装成模型答错 |
| prompt | **逐字节相同**，写死在一处 | 差一个字符就不是对照实验 |

**上限被吃掉不是「关思考」的理由，是「上限不够」的证据。** 本文旧版写的是「关掉思考模式，
否则推理预算吃掉 `max_tokens`、`content` 返回空字符串」——那是把**上限不够误诊成思考模式的问题**，
导致用错误的方式绕过了一个真 bug。正确做法是**读 API 的 `finish_reason`**：等于 `length`
就是被截断，该题记 **INVALID、不进分母**，然后把上限**提到题能跑完为止**。
实测：AIME 类题给 1200 是拦腰截断，提到 4096 仍不够最难的那几题——**最难的题会把上一档翻倍**。
**只要 INVALID 计数不为零，就是上限还在生效的红灯，不是可接受的损耗。**

配套四条不能省：
- **`reasoning_content` 作回落源**：`content` 为空时读它——否则思考模式样本全判 0。
- **要求模型以固定终止标记结束**（如 `FINAL: <答案>`），解析时取**最后一次**出现，
  不要只看最后一行——思考模式下最后一行可能是别的。模型不按格式输出时再走“全文最后一个候选 token”的兼底，
  但那层兼底有误判风险，**要单独计数、不要让格式失败混进质量信号**。
- 每题**独立请求**，`cache_prompt=false`（提示词缓存会让后续轮次的 PP 数字变成噪声）。
- **汇报带污染标记**：写 `19/23（其中 3 题 INVALID）`，不写一个干净的总分。

**出题先给主人审。** 把题目、评分看点、统一协议先摆出来等点头再跑——他会改题（难度档、领域、
约束、是否贴他当前课程/研究方向）。先摆题也顺带把歧义题（表述不清、多解、预设了立场）挡在跑批之前。

## 2. 题目要能程序化判分

判分类型够用的四种：`numeric`（正则抽数比数值）、`exact`（归一化后全等）、
`contains`（关键词表，容忍多种正确表述）、以及针对具体约束的定制判分
（如「恰好 10 个字」「3 个递减质数」——约束本身可程序化验证）。

**归一化要在比较前做**，否则会误判正确答案：下标/上标数字（模型写 `H₂O` 而 key 是 `H2O`）、
全角符号、`×`/`−` 这类变体。误判方向恒为「把对的判错」。

## 3. 题库自己也要验（最容易漏的一步）

**判分器测通了不等于答案对了。** 两道都要过：

1. **本地自测判分器**：喂合成输出（正确答案、错误答案、大小写变体），断言判分结论符合预期，
   再把判分器送出去。
2. **逐题核答案 key**——模型与 key 冲突时，**先手推一遍再判谁错**。
   实测：一道三人真假话的题，key 写错了，模型答对了，判分器忠实地把对的判成了 FAIL。
   模型「答错」是重新审视 key 的触发条件，不是结论。

## 4. 天花板效应：题库太容易就分不出高下

探针的目的是**拉开两个量化档的差距**。若参照档已经考到 95%+，两个档很可能都满分，
题库就废了。**量化损伤的特征是在能力边缘掉点**，题目必须落在失效边缘：

| 类型 | 为什么能区分 |
|---|---|
| 大数乘法 / 长运算链 | 量化误差在链上累积 |
| 多重约束指令（项数 + 首字母序列 + 格式） | 指令遵循最先被量化损伤 |
| 长尾事实召回（冷门年份/编号） | 权重被压后长尾先掉 |
| 多针检索 + 干扰项 | 同时考权重与 KV 量化 |
| 精确计数（「这段里有几个 X」） | 一碰就错，是最灵敏的一类 |

报告**分类准确率**，不只报总分——损伤是不均匀的，总分会被大量简单题掩盖。

## 5. 长上下文题的做法

按固定文本重复拼出长文档，把 needle 插在约 **60% 深度**（前后都有内容才考得住），
并保证 needle 用词在文中**唯一**（否则模型可以靠重复模式蒙对）。
自测构造函数：打印文档长度、token 量级、以及 needle 确实在文中。

## 6. 运行时坑

- **Windows 控制台是 GBK** → Python 输出 UTF-8 会被显示成乱码（中文类别名全花）。
  跑之前设 `PYTHONIOENCODING=utf-8`。
- **PowerShell 把 `a,b,c` 当数组** → 传逗号分隔的参数值必须加引号（`--ids 'nd1,nd2,nd3'`），
  否则会被拆成多个参数、过滤条件静默失效。
- **`--limit N` 取的是前 N 题**，而题库是分类排列的 → 冒烟测试只会覆盖第一个类别。
  另加一个按 id 过滤的开关，才能跨类别抽测。

## 7. 直连服务的调用形状（llama.cpp / OpenAI 兼容）

```bash
curl -sS --max-time 3600 http://<host>:<port>/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"local",
       "messages":[{"role":"user","content":"<prompt>"}],
       "chat_template_kwargs":{"enable_thinking":true},
       "cache_prompt":false}' \
  | jq -r '"== REASONING ==", (.choices[0].message.reasoning_content // "(无)"),
           "== ANSWER ==",    (.choices[0].message.content // "(空)"),
           "== META ==",      ("finish_reason: " + (.choices[0].finish_reason|tostring)
                              + "  completion_tokens: " + (.usage.completion_tokens|tostring))'
```

- **不传`temperature` / `top_k` / `max_tokens`**——见 §1。
- 思考在 **`message.reasoning_content`**，正式回答在 `message.content`。**两个都要打出来**。
- `finish_reason` 必须进场打印——它就是 §1 逆闸的输入。
- `--max-time` 给足，不设上限 + 开思考单题几分钟很正常。

**发批量命令前先用一条最小请求探真实返回结构（必做）**：字段名到底是 `reasoning_content` 还是
`reasoning`、有没有 `usage`、思考到底开没开——一行探针就验掉。
**没验就发出去的批量命令，字段名一错就是整批废品。** 同时报服务身份（`/v1/models` 取 name），
防止换错服务、把 A 的结果记成 B 的。

**生成批量命令时**：用 `json.dumps(..., ensure_ascii=False)` 生成 JSON body，**不要手写转义**——
中文、LaTeX（`\\`、`$`）、代码块（反引号）手写极易错；用单引号包 JSON 交给 shell 前先断言 body 里不含 `'`。

**交付形态**：主人惯用「**一条命令一道题**」，自己粘了跑再把原文贴回来。指令要能**独立粘贴运行**，
每条自带 REASONING / ANSWER / META 三段，并同一份命令清单落盘供重取。

## 8. 自由文本答案怎么判（没有 key 的题）

§2 的四类判分只覆盖**有标准答案**的题。跨领域简答题（推导 / 科研批判 / 工程判断 / 制度分析 /
代码解释）没有 key，只能**核对断言**——判分对象从「答得对不对」变成「**它说的每一句是不是真的**」。

**先立自己的标准答案，而且要用两条独立路径。**
数值题判分前自己算一遍：解析解 + 一条独立验证（数值积分 / 蒙特卡洛 / 另一种算法）。
两条一致才敢拿它去判别人。**只有一条路径的「标准答案」不是标准答案，是另一个待核的断言。**
（实例：一道功效题三家用同一错值，自己先被三条路径交叉核过才敢判它们错。）

**逐条回源，不看形式。** 模型产出的三类东西要分开核：

| 产出 | 失效形态 | 核法 |
|---|---|---|
| 引用（学者/书名/年份） | **编造一个不存在的人**，或把 A 的贡献挂在 B 名下；真名混排时假的那个也长得很真 | 逐条检索：人存不存在、书是不是真、那句话是不是他的 |
| 「工具输出」 | 把**记错的表值**包装成 `R 的 pt(...)` / `G*Power 给出`——带着权威感的错数 | 按它写的命令**真跑一遍**；跑出来不符即编造 |
| 案例（年份/机构/数字） | 时期标签看似合理但内部矛盾 | 逐个事实到源站核 |

**判分要看 reasoning 与 answer 的差集。** 模型可能在思考段**已经识破了问题**，
却在答案里把那段删掉、照题面执行。**只看答案永远发现不了——那半句只存在于差集里。**
把「察觉但删掉」单列一栏：它和「没察觉」是完全不同的画像（一个是能力，一个是选择）。

**数字类错误与知识类错误分开计。** 会算但会编引用、和不会算但引用老实，是两种完全不同的模型。
合成一个总分会把画像抹平——分开报才知道哪个能委派干活、哪个只能当检索用。

**题面本身也要过闸。** 自建题一旦范畴错位（拿不属于同一类的项并列）或自带立场
（维度选得使某一方天然占优、「要求中立」其实把某个立场当地面了），**三家模型会全部照做**——
因为没有一家会顶回题面。出题人先自己过一遍范畴/尺子/预设（见 `delivery-critic-gate` 闸 0），
否则**越工整的对比离题越远**。
