# 标记跨族探针实验（marker probe）

## When to Use
跑标记跨族判别矩阵（N4 类任务）、下载/验证对照模型 GGUF、向笔记本传模型，或在本机与笔记本之间调度探针推理时。

对 ChatML 族控制标记的「书写纪律」现象（直写→EOS 截流死亡 / 零件拼写 / bias crossover）做跨 tokenizer 家族的判别实验。词表含该标记单 token 的家族 A 类必死；裁决假说靠词表无整词、只有零件的家族看能否拼出字面量。

## 研究对话的载体自保（操作员模型选择与阵亡签名）

- 承载研究对话的 agent 自身也是 A 类受害者：在思考里概念性处理该标记（讨论机制、读词表元数据、写判据）就可能直接预测它，该 token 就是模型 eos_token_id 的本尊，服务端当场截流，回合变成空消息。输出纪律（占位符、chr() 构造）只管得住输出通道，管不住思考层。
- 操作规则：凡对话内容涉及标记概念，操作员模型选非 Qwen 族；Qwen 只当被试（API 实验对象，JSONL 落盘交互）。这条管「谁来操作」，与实验格设计里「谁当被试」是两回事，别混。
- 阵亡签名：助手消息 content 为空且无工具调用，紧跟在一次标记密集的工具输出（词表/模板/判据/元数据）之后，goal 重推循环轮轮空回复。认出签名就换载体开新会话重续——同一载体上重试没有恢复先例，别赌。死后的进度重建与交接照 unattended-mission-planning 的交接节办。

## 实验格设计
- 裁决格：词表无该标记整词的家族，用**官方原版 GGUF**（如 ggml-org 官方量化的 Gemma-3 系）。第三方 uncensored/heretic 微调量化一律不得当对照——微调改过 chat template 与 tokenizer 行为，会污染裁决。
- 官方出身的门禁适用于**一切基线**，不只对照 GGUF：任何本地模型文件（含 safetensors）当基线前，先读 README frontmatter 的 base_model 与 tags 确认出身——文件名含 Uncensored/Heretic/abliterated/HauhauCS 等即二创（aggressive abliteration 还常经 GGUF 往返双重转换，权重多一层转换扰动）。已用二创跑出的结论（如嵌入几何探针），论文化前必须官方原版复跑；二创版本身降格为「权重扰动是否改变几何/行为」的污染对照格，数据不浪费。
- CONTROL 格：词表含该标记整词的异家族模型（如 MiniCPM 系），预期行为类 Qwen 生产模型。注意：若该模型的 generation_config 同时把标记声明进 eos_token_id 数组，这一格就同时动了两个变量（词表 + EOS 声明），不能用来裁决「CONTROL 类型本身是否致停」。
- 判别「CONTROL 类型 vs EOS 声明」的格子必须满足：词表有整词、模型 generation_config 不声明它为 EOS、且该字符串不在 llama.cpp 加载器的按名点名清单里（源码 llama-vocab.cpp 硬编码 `<|eot_id|>`、ChatML 标记、`<end_of_turn>` 等——进谁家词表都会在加载时被收编为回合终止符，与 HF 侧声明无关）。用清单内标记做「非 EOS 控制 token」判别格是无效实验。
- 显著性标尺：「生成自家 EOS 会停」是定义推论不是发现；贡献只能落在——加载器按名点名机制、转义保护在量化档破功（非单调死亡率）、死亡刀口精确落在整词 tile 的物证（想提及、拼出来了、被杀）。写作时解释层重心放这三条。
- 开跑前先问「结果是否已被现有机制理论预判」：预判为必然的格子零信息增量，不跑（让任何家族提及自家回合终止符必停；词表有整词但不在点名清单的格在 llama.cpp 上必活）。指挥官判据：行为层实验若只是在量化已观察到的现象、源码审查若只是阐释已知实现（对引擎社区是常识），就是原地打转；要增量必须换证据层——行为 → 嵌入几何 → 逐层 hidden states → 激活干预。
- 主战格：生产 Qwen 系（词表含整词，A 类直接诱导=确定性死亡）。
- 验证 GGUF 词表有无整词：读 GGUF 字符串表（strings），字面量在 Python 里用 chr() 拼出来再搜——纪律要求任何通道不写标记原形。

## 探针训练后必做推理 sanity（2026-10-04 教训）

logistic 探针 AUC 满分 ≠ 可用：标准化 sd 下限过小（1e-6 级）会让训练集近常数维在分布外推理时爆炸（实测 z 到 113、分数 -4000、softmax 饱和 π 钉死）。AUC 是排序指标、对缩放不敏感，这类数值 bug 完全不被 AUC 捕获。规程：训练后立即对一条分布外样本（如生成上下文）跑推理，分数落在训练分数 ±3σ 带内才算训练完成；sd 下限取中位 sd 的 1%。

## teacher-forcing → generation 分布断裂（S6 影子教训）

- 单句模板 teacher-forcing 训练的浅层（embedding 层）探针，在自回归生成分布上激活范数漂移 1–2 个数量级、判别方向都可能翻转。跨分布使用前必须先在目标分布上测 ROC，别默认 hold-half AUC 可迁移。选层规则只按分布内 AUC 时，浅层往往与多个层**并列满分**——最终层号是平局规则挑的，不是证据挑的；报「选中第 X 层」之前先数有几个并列。

## 训练/评估脚本的静默故障家族（GPU 拉起前自查）

- 统计中间量用 float64 做数值稳定没问题，喂模型头之前必须显式 `.float()`：Welford/EMA 类标准化量是 double，Linear 头是 float，dtype 不一致要到第一次 forward 才炸——载入一次权重要几分钟，盲改重拉白烧一轮。
- hook-store 逐行取激活的模式：每行必须先对本行序列 fresh forward、再切片 store——hook 缓冲是共享的，不重跑前向就拿上一行的激活，无报错、纯静默数据污染，比崩溃贵得多。
- 探针训练脚本禁用全局 `torch.set_grad_enabled(False)`：头参数要 backward；特征前向用局部 `with torch.no_grad()` 包住即可。全局开关会把「特征不用梯度」和「全图不用梯度」混成一刀。
- 逐 token 流水线的观测-标签对位写死再评估：第 t 步的观测读到的是含 token t−1 的上下文，事件「可见时刻」= 事件位置+1；对位规则不写进分析器并自测，整张混淆矩阵全错而数字看起来正常。在线逐步读数与离线整段重放做等价性比对时同理：在线第 s 步的读数对应重放第 s−1 行的状态，差一格一致率静默掉 ~3 个点、伪装成仪器漂移。
- hook 返回类型按宿主架构写死：Qwen3.5 的 block 输出是裸张量（直接进 `_norm(x.float())`），probe/steer 类 forward hook 必须原样返回修正后的张量——包成元组会在下一层 AttributeError。改 hook 前先 grep 宿主 modeling 文件的输出消费方式；注入向量还要 `.to(h.dtype)` 对齐 BF16 权重，否则下一个 matmul dtype 崩。hook 里的元组判定禁写成双 `out[0]` 三元（`out[0] if not isinstance(out, tuple) else out[0]`）——张量分支会取走首行切片砍掉批维，报错落在几层之后的 rotary 头数不匹配（如 16 vs 64），离案发现场极远难定位；正确形态 `out[0] if isinstance(out, tuple) else out`。
- bundle/探针包跨脚本传递时**装载即统一上设备**：消费端逐个张量 `.to(dev)` 是打地鼠——同一根因连炸三次（权重 float 撞 CPU μ/σ、头在 CPU）才根治；规范是装载处一个 stage(bundle, dev) 一次性搬齐，消费端不许再碰 .cpu() 的原始张量。
- 采集与标注必须同一 runner 闭环：生成 runner 不跑 measure()，行里就没有 token_char_ranges/forms，事后标注器对全体行返回 None，影子门槛判定输出全零、看起来像「仪器无效」——实际是分析覆盖缺口。补标注可以事后在有权重/分词器的机器上跑（measure 只需 tokenizer），但 runner 里闭环是默认。
- margin 是带符号 z 差（z_w − 次名）：「w 上桌/逼近决策」= margin 高于负阈值或落在正区间，句中远离时是 −17 级深负。门语义写成「margin < 正阈值」会把句中步全部误触发（实测触发率 100%）；正确形态是带符号区间（决策候选带 = 0 < m < 细门值，合法带在其上）。
- hook 的状态缓冲字典在注册循环外建好再传入：列表推导里写 `store := {}` 每次迭代重新绑定一个空 dict，各 hook 写各自副本、消费端读到最后一个，报错落在别处的层号上。
- 用 find() 找锚再切片拼接改脚本前，先断言锚存在（find 返回 −1 时 `src[:-1]` 会把文件尾部卷进拼接点，整段代码被吞进调用行）；含三引号的替换交给 patch 工具，不在手写 python 字符串里嵌三引号。

- 后台长跑的输出别过滤后再挂管道（grep 管道块缓冲）：过滤条件一放，进度输出被 4KB 块缓冲吞住，90 分钟盲跑看不见一行。要看进度就落原始 log 文件再 grep 文件，或干脆不过滤（噪音行留给 log）。
- **Linux 上 Python 拿不到文件诞生时间**（os.stat 无 st_birthtime）：要 crtime 必须走 coreutils `stat -c %W` 批量调用；tar 解包件带着上游远古 mtime，按 mtime 分桶/排序会全体涌进「今天」——birth time 才是「加入项目时刻」的正确信号，且内容编辑不改 birth，适合重建历史。
- 按 mtime 重建 git 历史的成熟做法：crtime 分桶 → `git add` 显式路径清单 → `GIT_AUTHOR_DATE/GIT_COMMITTER_DATE` 设为桶时点逐桶提交；「nothing added to commit」要当成功路径处理（未跟踪文件存在时的措辞与「nothing to commit」不同）。
- 收集器排除条件写 `f == "README.md"` 这类纯文件名匹配会误伤全树同名文件——排除条件必须限定完整相对路径。
- ROCm HIP 分配器的「allocation failed ... retry」警告是缓存分配器自愈（释放缓存后重试成功），**不是抛错、不算 OOM、不触发 STUCK**——如实记进台账当压力事件即可；真正抛 torch.cuda.OutOfMemoryError 才按 OOM 纪律处理。

## 笔记本远程运行

- 后台 ssh 链会被本地会话终止连带杀掉（Windows 端无 nohup 语义）：要么前台跑带 `-o ServerAliveInterval=30`，要么远端用 `schtasks`/`start /b` 脱离；轮询远端进度用短 ssh + tasklist 计数。
- schtasks 拉起后 30–60 秒内用**独立 ssh 命令**读一次远端 log 尾：首行崩溃（未绑定变量、断言、分派漏分支）只写在 log 里，只看「log 存在 + 行数爬升」会把空转晚四分钟才暴露。轮询与探测期间每条 ssh 只发一条命令——cmd 的 `if exist ... (echo) else (echo)` 链之后接的其他命令会被静默吞掉。
- 给 stepwise 采集器加新臂时，臂表/分派之外必须同步检查尾段绑定行（stepwise 臂绑 `seq`、generate 臂绑 `out`）：只加分派不改绑定，新臂首行即 UnboundLocalError。
- 从 Windows 拉文本文件回 Linux：`ssh host 'type D:\path\file' | tr -d '\r' > local` 比 scp 路径转义可靠（scp 的 Windows 远端路径多种写法均试过失败）。

## 运行环境
- 生产 llama-server（8080/8081）：只读推理、单实例串行，不开第二实例、不重启不 kill。
- 生产栈与笔记本的**当前状态**唯一账本 = `~/Documents/Hermes/运维状态_20261006.md`——凡问「现在什么状态」先读该文件，不信记忆。
- GPU 实验窗口协议：干预/激活类实验要求 llama-server 停用（它驻留 ~98% 显存）；停/恢复是指挥官的 sudo，开跑前 `rocm-smi --showmeminfo vram` 复核空闲（几十 MB 级=空闲，25GB 级=生产占用——CPU 侧工序照做，GPU 臂挂起等窗口，别空等）。
- 万级前向的长跑（边缘化扫描、逐 token 再同步这类）一律 background+notify 起跑：前台超时会杀掉只在未来写盘的管线、零产出。写盘策略能逐行 append 就别「跑完一次性写」。
- 在线剖面默认 KV 增量解码（prefill 一次，每步喂 1 token 带缓存）：与整段重前向数学等价、只余 ULP 级核序差，等价性交给「在线读数 vs 离线重放一致率」门实测背书；整段重前向只留给等价性校准本身。实测把 17 流 × 60 步剖面从 45 分钟压到 44 秒。
- 贵信号（64 候选边缘化这类）走两遍法：快速在线遍只记触发标记与状态、不在线算，贵计算离线对触发步补算；64 个候选共享前缀拼成单次 batch 前向（~2s/位置），比逐候选全前向（~6.5s）快三倍。
- 排长跑前先报 ETA 与每步成本结构（每步几次前向 × 单次耗时 × 步数）；实际耗时结构性超估时停手改架构（KV/两遍/批量化），不原样硬重跑；用户喊停后，先用大白话讲清「这一步在做什么、钱花在哪」再谈恢复。
- 实验脚本一律 terminal 调 venv python 跑；execute_code 的 kernel python 无 torch，小段验证也用 venv 的 subprocess，别在 kernel 里 import torch。venv 调用前置 `env -u PYTHONPATH`（hermes 工具链会往 PYTHONPATH 注入不兼容的 numpy 把 venv 污染）。
- 干预/闭环类实验（读激活→判状态→控制输出）的栈已由指挥官裁定：**transformers 优先**（forward hook 取残差流 + LogitsProcessor 做采样前门控），**严禁 vLLM**，**不碰 llama.cpp C 层 hook**（裁定为难搞）。设计提案里不要再推 vllm-lens 或改 C 层这类路线——被否过一次。
- 笔记本 GPU 机：ssh 别名 `laptop-training`（密钥登录，模型目录 `D:/LLM/Models`）。传文件必须走别名，不要手写 `user@host`——大小写不匹配会覆盖 config 里的 User，publickey 直接拒。
- 传 GB 级模型走 WireGuard 隧道：先用 ~50MB 探针文件计时测吞吐（实测约 4.1 MB/s，据此估全程时长），再后台化跑（前台会在几分钟处超时），完成后 certutil -hashfile SHA256 与源端 sha256sum 对账；Windows 目标目录先 `if not exist ... mkdir`（scp 不自动建）。官方原版模型优先在目标机 `hf download` 直下（走目标机带宽，比经 VPN 推快且省本机磁盘 IO）；仅二创/私有文件才走 VPN 推送。
- Windows 查磁盘空间用 `Get-Volume`，`wmic` 已废。

## 协议与落盘
- Prompt 全英文 verbatim 协议（"Repeat the following sentence verbatim and nothing else: ..."），各格同构，结果可直接进同一张表。
- 结果落盘 jsonl（content/reasoning/bias/finish 等字段，脚本在 `灵感笔记调研_20260929/framework/`）；脚本里 INSTR 常量是 prompt 权威，jsonl 不存 prompt 字段——判读时回看脚本。
- 指挥官铁律：本机 RAM 已满，**任何模型相关实验（含嵌入张量读取、逐层探针这类轻加载）一律在笔记本跑**，本机只做脚本编写、文件传输、结果汇总；跑批前仍核对本机 RAM/GPU 占用。
- Windows 侧检查 GGUF 字段/源码 grep：本地写 Python 脚本（用 gguf 库 `fields[...].contents()` 读，字符串用 chr() 拼标记）→ scp 到笔记本 → ssh 跑 → 输出管道过 iconv。findstr 多模式和引号内联 python 穿 SSH 会静默吞输出（GBK/引号双重坑），别在 ssh 命令行里内联复杂 Python。
- 词表核验三源交叉：GGUF 头（token_type，3=CONTROL；tokenizer.ggml.eos_token_id）、HF 侧 generation_config.json（eos_token_id 可以是数组）、tokenizer_config/tokenizer.json 的 added_tokens（special:true 注册）。三层可能互相矛盾（GGUF 头只声明基础 EOS，HF 侧声明补充 EOS），汇报时分层写清，别只报一层。
- GGUF KV 键名不统一，先列键再取值：chat template 常在 `tokenizer.chat_template` 而**不是** `tokenizer.ggml.chat_template`，按后者查会静默返回空、被误报成「无模板」。先跑一个只打键名不打值的枚举脚本（顺带满足 D1，值里常含标记原形）看清全部键，再按键名取值。同一 GGUF 可能并存多个互相矛盾的 eos 键（基础键 + 架构前缀键，如 `qwen4exp.ple.eos_token_id` 与 `tokenizer.ggml.eos_token_id` 各说各话），取值时把每个都列出并标注归属，不许只报一个。
- HF 侧停止符分三层实测，别拿 tokenizer.eos_token_id 当停止符：L1 出厂文件（config.json 顶层 `eos_token_id` 常为 None，真值在嵌套层如 `text_config.eos_token_id`；`generation_config.json` 可能根本不存在，此时生成配置来自 config.json 嵌套层）；L2 transformers 载入后 `model.generation_config.eos_token_id`——**这才是 generate() 的实际停止条件**；L3 脚本传给 generate() 的覆盖。三层可以各不相同，报告分层写。
- 「生产对话模板」以启动脚本为准，不是 GGUF 内嵌模板：llama-server 一旦带 `--chat-template-file`，内嵌 chat_template 在生产里就是死的。报模板事实前先读 `.sh.stable` 里那一行，内嵌与 override 两份都测、分两行写，注明哪份真正在跑。

## 表示层实验（嵌入几何 / logit lens / patching）
- 上模型前读 config/README 确认架构，别假设纯 Transformer：Qwen3.5-4B 是 hybrid（32 层 = 24 层 Mamba2 线性注意力 + 8 层全注意力，索引 3/7/11/15/19/23/27/31），层位解读规则不同。
- logit lens：`output_hidden_states=True` 逐层读 residual stream 两类层都可行，但 Mamba2 层与注意力层的曲线分开画、不混排；激活 patching 选点优先全注意力层——Mamba2 的 SSM 状态 patching 是另一套工具，首轮不碰。
- 笔记本 torch 默认 CPU 版；跑逐层 hidden states 前先装 CUDA 轮子，`device_map="cuda"` 还需先 pip 装 accelerate（缺了直接 ImportError，装上即跑通）。4B BF16 权重约 8GB，12GB 卡装小上下文可行，装不下就 CPU 慢跑（能完成）。
- 竞争假说的可分离预测落笔在先（跑之前写进任务卡），否定结果照常入档——这是指挥官明令的防过度包装护栏：不预注册流程，但判据必须事先写死。
- 再同步/稳定性实验用贪心（τ=0）让「重合」有确定意义：先双跑基线验确定性（同输入两次 token 流不一致 = 栈非确定性，修确定性开关重跑，不写负结果）；T_res = 首个永久重合点。别拿状态空间的放大倍数外推行为不稳定——状态放大与离散通道完美吸收（单发扰动 T_res=0）可以并存，行为稳定性要看离散通道自己的测量。

## 模板纪律注入部署（让规则每轮生效）
- 需要「每一轮都生效、压缩不丢」的行为纪律（书写纪律、汇报可读性纪律这类）住 chat template 注入块，不住任务卡——任务卡只在任务开头被读一次，压缩后只剩摘要；按需加载的 skill 正文同样不抗压缩。模板注入块是 system 块尾部（terse 之后），每轮请求都带，是这类规则唯一稳定生效位。
- 纪律块纪律：块自身不得含标记原形字面量（不得成为新诱发源）；讲后果不讲术语；正向措辞。每条纪律带独立 jinja kwarg 开关（默认开），供 A/B 干净切换。
- 部署流程（v1 已验证，v2 照做）：overlay 改模板 → 本地 jinja2 渲染验证（有工具/无工具两场景，断言注入块顺序与开关关闭时干净回落）→ 复制到 `~/Documents/LLM/Models/Qwen-Sharp-Chat-Templates/` 并 sha256 对账 → 生产脚本 `.sh.stable` 的 `--chat-template-file` 行改指新版（diff 只许这一行，先备份，`bash -n` 过）→ 不擅自重启服务，重启窗口由指挥官定，重启后 /props 验证模板字段含新块才算生效。
- 现状：生产模板 = `chat_template_discipline_v2.jinja`（token 纪律块 + 汇报可读性纪律块，开关 `token_discipline` / `readability`，均默认开、互不干扰；源副本在 `灵感笔记调研_20260929/overlay/`，对照说明同目录）。改动只加块、不动既有 terse/discipline 拼装逻辑。

## 采集管线排产与落盘（on-policy 数据）

- span 偏移与 surface 必须同源：在清洗/归一化后的文本上算偏移，surface 就从同一份清洗后文本切。两份文本长度不同（如把标记序列换成固定占位符）时混用，会在第一次替换后整体错位，回声归因逐条变错。修法是**等长掩码**：标记序列替换成同长度 ASCII 字符（n 个 `=`），偏移在原文与掩码文本间恒等，错位在构造上不可能发生。掩码必须**正则惰性**（不含数字、不含词表名）——占位符里的数字会被数字类正则命中，凭空造出假 span。
- 表面形式先分「发射 E / 拼写 S」再统计：解码文本里出现标记的表面形式，可能是 gen_tokens 里真实标记 token 渲染出来的（**使用**），也可能是普通 token 逐字符拼出来的（**提及**）。不分就等于把自发发射记成提及命中，直接污染主表。判据：该字符区间恰等于某标记 token 的字符区间 ⇒ E，否则 S；E 区间等长掩码后不进任何标签层，只记 self_emitted。token→字符区间用累积解码 `len(tok.decode(gids[:j+1]))` 取边界，别逐 token decode——边界空白处理与整段解码不等价。
- 特殊形式计数前先分类：把所有特殊形式统一换成同一个占位符再 count，得到的是**全部特殊形式总数**，不是目标形式的计数（目标 8 + 其他 15 = 23，会被报成「目标 23 处」）。按 kind 分列计数，报告写清分母。
- 排产规模先对验收下限：生成 plan 后立刻 assert 各臂样本数 ≥ 任务卡下限再开跑。种子数乘 prompt 数是乘出来的，跑得完不等于达标。
- 自发发射与强制注入分字段落盘：「模型自己发没发」与「仪器能不能看见该位」是两个观测通道，合并统计会把行为和可见性混成一个变量。U 位（使用态）按强制注入定义时，meta 里写明定义与注入位置。
- **采集器字段随版本演进，分析脚本必须带兼容层**：mid-project 新增的字段（如替换结束步）在旧代 jsonl 行里不存在，直接读会 KeyError 杀掉整批统计。读「新字段」前先按臂抽样探测 schema（查 key 在不在），缺失时按生成规则回推（例：旧 E 臂行 splice_end = splice_step + 路径长度 − 1），输出里标注「回推」。同项目混存两代采集器数据是常态，不是异常。
- **零成本复用分析攒成单一批次落盘**：纯 CPU、只读已有遥测的统计（逐臂计数、对齐轨迹、相图、留一验证）合成一个 stats JSON + sha16 指纹 + 笔记档指针——散落的小数字没有档就等于没算过，下一轮还会被当成「要做的事」重列。
- **当轮承诺当轮落盘**：每轮收尾扫一遍本轮口头答应的产出（统计、图、文档、存档），没落的当场落盘或写进任务卡欠账节——「要做的」跨轮未落即成欠账，会被点名催还。

## 探针与判决方法论（S1/S1b 定型）
- hold-half 探针：训练折拟合、**留出折**打分——把训练折分数当测试分算 AUC 会虚高且静默毁掉判决；脚本里 fit 和 score 必须是两个函数（fit 返回参数，score 打分），写反一次整批数据作废重跑。
- 判决计算先排 NaN 再取 max/min：逐层指标里混一个 NaN 会让 max() 返回 NaN、判决打印出假结果——先在干净列表上算判决值，再对照冻结阈值。
- 冻结判据遇算法歧义（如 in-sample vs out-of-fold 探针分数）：两个口径都跑，要求同侧同向才落判决，两口径数值都写进报告。
- 冻结判据发现空缺时写**补遗文件**冻结补充定义，绝不改母件——母件哈希已被记录，回头改等于伪造预注册。补遗自带时间戳与哈希，两个哈希一起进数据集头部；补遗同样必须早于采集落盘。空缺的典型形态是「同一表面形式有两种成因」这类测量归属没写死的情况。
- 交接卡/摘要里的数字一律回原文复测再引用。实测与转述不一致时，在交付物里单列一张更正表（转述值 / 实测值 / 出错原因），不要只在正文里悄悄用对的数——上一棒的错值还留在别人的读取记录里，会继续被引用。
- 探针从嵌入层之后第一层就满分分离 = 词汇信息的即时前传（lexical leakage），不是「中后层涌现的表征」——判据字面满足但机制解读必须降级标注，禁止把「形式通过」写成「机制成立」。
- transformers 的 `apply_chat_template` 可能返回 BatchEncoding 而非 tensor——脚本里统一归一化（`ids["input_ids"]`），否则下游 .to(device) 静默炸。
- 跨条件激活 patching 必须 token 对齐配对：两臂 prompt 除被交换的单 token 槽位外逐 token 相同（做法：把差异词放 prompt 末尾，决策位=末位，双臂等长，assert 对齐）。跨臂长度不等的整段激活互换会撞 RoPE 形状直接崩；且 tokenizer 会把差异词前的空格并入 token，后缀放法会悄悄破坏对齐——差异 token 只能放末尾。
- patching 脚本本地冒烟用 jinja2/torch 前先确认 Hermes 内置 python 装没装（本机常缺，pip 走清华镜像补装即可）；torch.topk 返回值解包用 `zip(*torch.topk(...))`，直接解包 namedtuple 到两标量会炸。
- 笔记本跑 hybrid 模型逐层 hidden states 无 causal_conv1d / flash-linear-attention 时 PyTorch 参考实现可跑通（慢但数值可信），装这两个包纯提速，不是前置条件。
- 长上下文臂（≥100k token）排产前先跑单臂可行性探针（几分钟级）再正式排批——hybrid 模型 head_dim=256 时 SDPA 快后端可能全不可用（flash 未编译、mem-efficient/cuDNN runtime disabled），落到 math 后端 = 注意力矩阵物化、显存随长度平方涨；小显存卡装完 BF16 权重后激活余量极小，跑批中途撞墙等于整批白跑。显存账要在纸面上先算：权重 + 注意力矩阵（L² × head 数）。
- 显存容错捕获必须写 `except (torch.cuda.OutOfMemoryError, RuntimeError)`——CUDA 异步执行，OOM 常在后续任意调用点以 AcceleratorError（RuntimeError 子类）抛出，只捕 OutOfMemoryError 会直接崩整批；捕获后 `torch.cuda.empty_cache()` 再继续。
- 判据冻结后若发现物理不可执行（如深臂超卡），不许偷改判据硬跑——按冻结判据判得了的臂出判决，判不了的臂如实标「物理不可执行」进待拍板清单（出路：更大卡/降样重冻/留 limitation）。
- 冻结判据时逐字自查每个形容词：「稳定」「显著」「明显」这类词必须当场配数值门槛——漏写一个，结果落进噪声带就只能报「半格」、无法按冻结措辞判决，判决权只能交回指挥官。
- 区分「理论的射程边界」与「理论有误」：干预把分布推动了但扳不动 argmax、而理论从未承诺 argmax 翻转时，如实报「边界被圈清」而不是判胜或判败；理论承诺了却没发生的才是证伪。两种都照常入档、不自裁。
- 逐 token jsonl 里 meta 行常写在其样本的 token 行**之后**，且 token 行不带样本 id——按「最近的前一个 meta 行」分组会把 token 整体错位一个样本，逐样本统计全错。分组只认显式 id 字段；核对每样本行数与 meta 里声明的 n_gen 一致后才用。

## 三分类探针与停止抑制边界（M/U/O，指挥官铁律）

- 探针状态空间**至少三类**，构成完整全集：M=提及（S 类形式出现）、U=使用（真实标记发射）、O=其他（替换/白话/跳过/无关）。二类全集装不下真实出口分布（抑制门下「其他」质量可达 60%），二态滤波的统计必偏——「其他」不是垃圾类，是决策上「不要碰」的状态。
- U 细分 **U-l（合法收尾，永远放行）/ U-p（过早终止，唯一抑制对象）**：合法性裁决归外层确定性任务状态机，探针只读内部状态。原则是防过早、不禁停止——模型在「我做完了没有」上不可靠（拼写提交后中位 3 步塌回使用即自欺实证）。
- 标签机械重建走**单一事实源**：一个 labels 模块供全部下游分析共用；标签只来自冻结账本字段（forms 的 cls/kind、gen_tokens），逐行与行级汇总字段互验（U 事件数对 self_emitted_pos、M 事件数对 n_spell），零失配才过闸。表单-token 覆盖判定用开首闭尾重叠（`T[j][0] < e and T[j][1] > s`）——闭首变体在表单首字符恰落 token 边界时漏掉首段，拼写提交行全体踩中。配方细节见 `references/three-class-labeling.md`。
- 一切比例带 Wilson CI（n=30 的半宽约 0.18）；M 自然事件稀缺时用干预提交态做构造性增广，meta 标「构造 vs 采样」，禁混计。
- 选层判据在**目标工作分布**上打（跨分布断裂见上文 teacher-forcing 节），禁用训练分布的层位表。
- 门控读数必须用**任务匹配的头**：语境头（「标记形式是否在可见上下文中」）是在场检测器，事件进入上下文后 1 步才点亮、且标记话题对话里几乎恒亮——拿它做发射门控 P* 必崩（实测 0.008，R* 反而 1.0）。门控要意图头（P(未来 k 步内事件)）；语境头降级为诊断读数。两头分工写进判据。
- 意图头训练量与类平衡是门槛的直接决定因素，不是调参选项：单 epoch + 事件窗稀疏（M 自然事件个位数）+ 类权重不足，训出 macroF1 0.22、P_M=0.002 的头，P2/K5 门槛必挂。已验证的重训配方（四门全过）：**选层跟决策通路走**（梯度对齐的深层带三层拼接特征，早层与决策方向近正交必死）+ 多 epoch 早停 + 事件窗过采样至 ~8% + 双分支头（two-layer MLP 与 linear 并联读同一状态）+ 打乱标签控制任务（macroF1 ≈ 3 类 chance 才算读信号而非记忆）+ 影子行 OOD 门（事件检出延迟 ≤3 步 + 状态级精确率门槛）——四门缺一不可，OOD 门防的是「分布内满分、上线全零」。
- 预注册的数字域与代码逐字对齐：判据写「取某臂全部步的中位」就把该臂行过滤出来再算——标定/统计脚本默认全集样本会把异臂行混进抽样域，中位数静默漂移。
- 派生指标按语义命名并核对方向再落判决：churn 类指标 = 1 − 重叠率；把重叠率当 churn 上报，会把「干净」读成「炸弹」、判决整体反向。每个派生指标落盘前问一次「数值越大是越乱还是越像」，报告里写明定义式。
- 预注册里给「新旧判决冲突」留一条自动改判条款：新网格结果与旧判决矛盾 → 旧审计判 INVALID、修正后重跑、以重跑为准。这类条款是计分 bug 的安全网——预先写了它，冲突出现当天就能定位到错的一边，不用臆测谁对。
- 边缘化读数的位置语义先写死：状态 s 预测 token s+1；决策前一位的 p₂(w) 是回声概率，horizon-2 信号在决策前两位。位置标签按「该位的 p₂ 意味着什么」命名，不按索引算术命名——错一格就把回声当决策、预告当回声，主判据整个倒置。
- U-l 群体的测点是自然收尾决策步，不是 prompt 末位：抑制器安全性的判据是合法收尾 margin 分布。sep-收尾行要同时读 w-margin（抑制剂量若把 U-p 的 margin 压进 sep 行的 w 值域即误伤合法收尾）。两群体间隔比 R = M_ul/M_up ≥ 2 → 固定剂量可分离、细门放两带中点；<1.5 → 无间隙、探针主门强制。
- 教师 p₂ 的尖峰结构已实测定型：尖峰精确落在事件前一步（horizon-2 窗），而尖峰步的 margin 跨事件横跨 −2 到 −25——固定阈值触发是错误的函数形式，怎么调都抓不全。在线形态走蒸馏：离线用教师 p₂ 给状态打标签、按流划分训/验（任何流不得同现两侧）破循环性，学生头与探针同配方每步读；合法性判定仍归状态机，头只报「w 将至」。
- 闭环实验的任务完成判定按**当前流内容**判（拼词路径在本流完成才 done；没完成则一切 w 发射皆过早），禁沿用历史拼接账本的完成位置——换数值域/解码方式的轨迹整体漂移，账本位置要么早关门漏抑制、要么晚关门误伤合法端。

## 轨迹约定与跨臂读出（E9/K5→E9-e2 代际，2026-10-05）

- 复用任何已录轨迹前先做**约定探针**：重放判据不只比 argmax（近平局钝），要用 z_w 逐值对（MAE ≤0.01 量级）判约定。实测教训：k5a 在线剖面把 prompt 喂了两遍（「双提示」状态，z_w MAE 0.0003 vs 单提示 2.35、token 12/12 vs 0/12），而同文件里 p2fill 补算的 s₃ 列却是单提示坐标——一份文件两套坐标并存，不探针就混用，教师和特征会错位而不报错。
- **混合注意力架构的 KV 缓存不能批量复制**：transformers 5.18 的 LinearAttentionLayer 没有 batch_repeat_interleave，deepcopy+repeat 快路径首步即 AttributeError。64 候选边缘化教师直接走「64×(前缀+1) 单批全重前向」（p2fill 同款），prefix 变长时用 logits_to_keep=1 压 logits 显存；混合层参考内核慢属正常，**别为提速装 flash-linear-attention/causal-conv1d**——换内核=换数值，与既往各包的可比性优先于速度。
- **跨臂读出不迁移是在策略监测的硬约束**：e67 拼接臂 41 正样本训出的报警头，臂内 alarm 0.976、到在策略状态字面量级 0（连教师 0.93 的强尖峰也读 0.0003）；对照 P1v2（在策略语料训练）影子 OOD 9/9 可迁移。在策略监测器必须用在策略正样本训；接手语料先查**正样本的臂分布**——正样本全落一臂时，(a)/(b) 类判据实际变成纯跨臂考题。
- **划分先于训练冻结，但冻结后要审计事件的落位运气**：标签盲 ≠ 事件盲——「val=最先两条有 W 发射的 spell 流」恰好选中两条弱尖峰流（0.235/0.160），强尖峰全在 OOD/disabled，主判据 (b) 在 val 上空集。规则无泄漏照样可以把判据考成空题，报告里要写明 n_events 落位。
- **回归头别用无权 MSE 扛秩判据**：~19% 正例率 + 稀疏大值目标下，纯 MSE 向均值收缩，秩相关连臂内都负（实测 −0.22，同时同特征的 CE 头臂内 0.976）。保真/秩类副判据用秩感知损失或 log/sqrt 变换目标，或干脆由分类头兼报连续分位。
- **预注册里预写「唤醒分级」**：哪些结果必须停下问指挥官（如阴性主条款触发=观测栈定稿变更）、哪些自行处置+记待拍板——阴性也有停机语义，写清楚当晚就能执行，不用临场猜。
- **包终态后同步改交接卡的「下一个待执行包」**：卡上留着「待发 Goal」而包已跑完，下一个小喵会按旧卡重复开包。

## 纲领对账、库存盘点与仓库卫生（2026-10-06 纠偏代际）

- **对账基准锚定原纲领**：每份报告「对总目标的意义」一栏的总目标，必须是原纲领文档（Note B 背景调研深入版）或指挥官显式改纲后的版本，禁止拿上一步任务卡的目标当基准打分；任务卡为可执行性收窄纲领时，收窄要显式登记，且每包报告回头对原纲领对一次表。机制：基准随任务卡静默漂移后，逐环打分再高也只是给收窄后的目标记账——六夜深挖无人对表，直到指挥官拿原纲领对照才暴露。

## 样本量与构念效度审计（探针/分类器类实验的交付前必查）

数字全部可复算不等于结论成立——判据管的是阈值，管不到「有没有资格判」。以下六条在任何探针训练/评测报告落盘前逐条过：

1. **刺激来源必须声明。** 训练与评测文本是自己写的还是外部语料的，报告开头一行写清。自编刺激检验的是自己提出的概念区分，没有外部锚点就没有纠错入口（与知识库禁 AI 自生成定义同理）。整改方向：模型真实生成轨迹（天然含「使用」条件）、公开多轮语料。
2. **有效样本单元 ≠ 行数。** 真值在样本内恒定时，一个 prompt 就是一个观测单元，逐 token 行只是它的重复采样。报任何统计量前先数独立单元数，并附置信区间。
3. **报 AUC 前先算它的分辨率。** 单折 AUC 粒度 = 1/(n_pos·n_neg)。层间或条件间之差小于一个序对就是噪声，禁止据此排序、选层或宣称某层更强。
4. **并列必须数出来。** 多层/多条件同分时写「N 路并列，由平局规则决定」，不许写成「规则选中了 X」暗示证据偏向该项。
5. **交叉验证按构造族切分。** 同一句式/模板的两臂被拆进 fit 与 hold 时，留出集不含任何新构造——测的是族内换词泛化，不是对新构造的泛化。声称 hold-half 前先确认留出侧没有训练侧见过的构造。
6. **构念必须被独立操纵。** 只动一个因子（表面形式）却声称两个变量（语用状态 + 表面形式）时，训出的探针按构造只能检测被操纵那一轴。设计期就画 2×2 因子格，两轴各自操纵，跨填充做 leave-one-filler-out。

规模门槛与公式、审计脚本骨架见 `references/probe-validity-audit.md`。低于门槛的 AUC 表只能当路标，不能当判决。

## 工程侧：标记卫生（回放面防线）

研究之外，生产侧对标记的处置有一组固定语义（tiered 插件在 wire 面执行孤儿清扫；家族表与 lcm-x 共用）：

- **家族表**（清单源 = lcm-x `escalation.py` 两套正则）：闭合对 = `<think|thinking|reasoning|thought|REASONING_SCRATCHPAD>…</同>`（IGNORECASE，开标签容属性）；起点检测另覆盖管道形（`<|`+`start_of_?`+词+`|>`）、方括号形、散文中缀形——检测形只做判定，不进清扫（无配对语义、误伤面大）。
- **清扫语义 = 孤儿-only**：按（家族, 标签名）分栈、左到右贪心配对；只删配对失败者，成对的一律原样保留；复制即变、幂等、确定性。控制 rails（im_start / im_end）同法配对，rails 字面量一律 chr() 拼装。
- **范围按分层取证收窄**：生产普查里工具/用户消息的命中绝大多数是**引用**（读模板/代码/文档）；清扫 v1 只扫 assistant 文本；扩面留指针。
- **计数取证纪律**：宽松 LIKE 的原始命中数会把引用当泄漏——按 role 分组 + 严格前缀（`content LIKE '<前缀>%'`）+ DISTINCT 计数再下结论——先分层，再下口。

算法、取证 SQL 配方与代码通道纪律见 `references/marker-hygiene.md`。
