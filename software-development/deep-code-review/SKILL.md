# 自研件深度审查工作流（多轮 · 文件级）

## When to Use（触发）

- 主人判前一次审查「太泛、对代码逻辑把握不清晰」后的重做。或任何要求结论逐条可追溯的代码审查。

## 工序（R0–R6。每轮 = 批写文件 + 任务卡 Progress 更新 + 反思三行）

1. **R0 立档**：date 记 T+0。逐文件 sha256/行数/mtime 清单。判定台账骨架。任务卡与 /goal 都写进文件（Progress 节防会话阵亡，续跑不重做）。
2. **R1/R2 逐文件精读**：每文件一份分析，覆盖七项。职责一句话，公开接口逐函数登记。接口记录带签名、入参、出参、异常、调用方行号。逻辑走读逐段带行号，记依赖耦合与状态副作用。初判候选只记不判，附反思三行。集成面按「接口摘要」粒度。
3. **接口契约表**：跨文件编号 C-1…Cn：谁调谁、签名、返回值语义、失败行为。
4. **模块聚合**：文件→模块 M1…Mn（职责/接口/依赖）。模块表直接充当 draw.io 元素映射。
5. **对照推演**：每条候选先查上游原库/官方文档/文献（带 URL 或路径行号），再写前提→推理→结论。
6. **判定四件套**：①证据（逐字引用+路径行号）②参考（出处。缺失写「未找到」）③逻辑推演 ④决定（严重度+影响面）。缺一不算数。禁凭记忆下判。
7. **报告**：五线头开头 + 上层人话版 + 下层技术细节。drawio 用 mxfile XML（节点=模块、边=关系标签），写完跑 XML 良构检查（ElementTree 可解析、无重复 id、无悬挂边）。
8. **R6 自审对账**：四件套机械复核（反向搜索无证据/无参考的条目）。与前版报告列差异清单（升级/修正/关闭/新增）。

## 看板评审卡模式（看板派发评审卡时）

- **先定界再精读**：`git diff <base>..HEAD --stat` 定出审查范围，只精读 diff 与其直接调用点。千行级集成文件（数千行）按锚点行号靶向读，不把整仓当审查对象。
- **交付双轨**：台账文件写进永久路径（判定四件套本体）+ 卡内回报发现计数（按严重度分级）。计数是扫读入口，台账是证据本体，两者都要有。
- **行为级 ≠ 行级**：测试全绿不等于行级逐行核验，责任边界要两本账分开列。「测试覆盖了」不能当「我逐行读过」说。
- **多镜头并行时**：卡体里写明自己的镜头、以及其他镜头已覆盖的部分。职责是攻别人批掉之外的部分，不是重复同一段阅读。

## 铁律（踩过的坑）

- **先回设计会话原文定「这层为什么存在」，再拿官方硬规则定「边界在哪」**。代码 docstring 的自述 ≠ 设计。把「建议」级规则误读成硬规定会得出反向结论。
- 千行级大文件只读关键段时，用接口契约表反查调用点补盲区。
- 推断与已核验分开标注。有探针条件先跑实证再写定性。探针脚本放 scratch，闲置 24h 系统就删，关键输出要转写进台账。沙箱探针按 `hermes-local-ops-troubleshooting` 的生产启动链搭，别用裸解释器。
- 审查对象只读、验证走隔离沙箱、生产零写入。改动一律「只出清单不改码」，等主人逐条拍板。
- **字符串取证计数必须严格锚定**。宽松子串匹配会把「引用了该字符串的普通内容」也计进去，结果虚高。源码或文档自身含该串时，读取它们产生的输出同样会计入。先精确/前缀匹配再计数，再拿另一权威源（生产转录库、原件拷贝）交叉对照。
- **审查后的变更或新发现不改写快照**：逐文件分析与台账正文保持冻结。另加带日期的「附记」（变更内容、新旧 sha256、新证据指针）。历史文件是快照，不是草稿。
- 交付前机械检查：交付物清单逐项点名、XML 良构、全文禁词。
