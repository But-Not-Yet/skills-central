# 克隆参考音频的素材挖掘（B 站等 UGC 源）

## 源类型优先级（先天干净度排序）

1. **官方联动语音包**（导航语音包、游戏/地图联动）——录音棚录制、逐句短句、间隙实测 -180dB 纯静音、御姐/标准腔。搜「<角色/主播名> 语音包」「<名> 导航」。这是被低估的金矿：克隆 prompt 的理想形态。
2. **官方音声/电台栏目**（主题音声、ASMR 栏目）——录音棚标准，但注意：电台类常全程无静音（连轴播）。绝对阈值静音检测失效，改用「相对能量谷底」（局部 0.3s 窗比周围 1.5s 低 ≥6dB）找切点。且大量放歌，唱歌段混在说话段里。
3. **直播切片**——音色情感最自然，但普遍带垫乐 BGM、高能段语速过快。切片标题带「asmr/窃窃私语/电台/读评论」的比「高能/整活」干净概率高。
4. **唱歌切片**——必带伴奏，做 prompt 直接排除（除非走 demucs）。

## B 站检索操作

- yt-dlp 查询：`bilisearchN:<关键词>`。必须带 `--user-agent "Mozilla/5.0 ... Chrome/126"` + `--add-header "Referer:https://www.bilibili.com/"`，否则 412。
- `--flat-playlist` 下 bilisearch 拿不到标题（全 NA），去掉 flat 逐条取（慢但能挑）。
- 个别视频（大会员/付费）报 `No video formats found!`——不是网络问题，换源，别重试。
- 下载：`-f bestaudio -x --audio-format m4a`，再 ffmpeg 转 24kHz 单声道 WAV。

## 自动内容分类的坑（都翻过车，指标只当粗筛）

- **间隙能量法**。BGM 垫在语音底下时间隙检测看不见（语音一停音乐才露馅，但间隙短/电平被噪声底掩盖）。
- **「最静秒」判无 BGM**：最静的往往是器乐间奏，据此选切点会切到唱歌段。
- **基频平滑度判唱歌**：带伴奏的人声自相关被伴奏带偏，判据无区分度（全判「说话」）。
- **窄带稳定谱峰**：直播垫乐音量起伏大，不满足「跨帧稳定」假设，漏报。
- **PSD/SNR 排序**：笑声能量被计入「语音」导致 SNR 虚高，排出来的全是笑声段。笑声另用基频筛（笑声帧 F0>300Hz）。
- 结论：任何「这段没 BGM/不是唱歌」的自动判定都只是缩小候选范围。**交付前一律发片段给主人耳朵裁决**。耳朵连否几批就换源类型或上 demucs，不要继续修指标。

## 交互式裁剪面板（主人选点用）

音频裁剪点让主人自己定时，做一个 ::preview 波形面板：音频 **base64 内嵌进 HTML**（预览沙箱 fetch 相对路径会失败）。canvas 画包络 + 点击设裁剪线 + 试听按钮（WebAudio `start(0, a, b)`）+ `window.hermes.send()` 回报裁剪值。预置值放在能量谷底（语音结束后的静音处）。
