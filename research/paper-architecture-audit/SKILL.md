# 论文架构审计与想法对撞

## When to Use

主人贴来一篇或一组论文，问「这方法到底行不行」「帮我总结」「我的想法站不站得住」「邮件怎么回」。适用于带附录、系统提示、API 清单、代码的 systems / robotics / ML 论文。**只做文献新颖性检索**（「有没有人做过」）走 idea-background-research；**只核引用数字**走 literature-verification。对外回信的形状与语气见 `references/advisor-email.md`。

## 铁律（always-on）

1. **先读实现细节，再评方法**。附录里的系统提示、API 清单、约束表、solver 失败原因清单，比正文摘要更能说明它实际在做什么。正文三句话、附录三十页的时候，判断力只能建立在附录上。
2. **分清算的、学的、被约束的三件事**。同一个系统里常混着闭式推导、学习模型、硬约束。判能力之前先拆开——很多「模型很聪明」其实是公式在干活。
3. **查数值是不是闭式可推**。拿论文自己给的一个数，反推它是否由结构选择决定。能精确复现（如 $v_z = gT/2$ 与论文给的 1.962 吻合到小数）的那部分不是学出来的，是可计算的。这条决定「要学的东西」还剩多少。
4. **检查规格语言的表达力边界**。接口能写什么、写不出来的去哪了。表达不了的东西不会报错，会被静默替换成最近的可行写法——这是最危险的一类失败，因为它看起来像成功。
5. **检查它无法发出信号的失败**。有没有拒绝通道？输出格式是否禁止说「做不到」？某个分支（如「一轮都不可行」）是否根本没定义？裁判是否与生成器同族（自指）？
6. **层与层不许互相背书**。解析器、求解器、对象动力学的性质各归各：求解器只判可行，不判「轨迹等于意图」；解析器确定，不代表整条链确定。跨层宣称之前先找出两层之间唯一的接口是什么。
7. **给主人的想法定位承重墙**。先确认他认哪一段是核心价值，从那一段往上建。把核心判成「效率优化」是误判，会把整轮讨论带偏。
8. **自己的过度宣称被质疑时，回一手源重推，错就明说改口**。不许加限定语硬撑（「严格说其实……」）。改口要给出修正后更窄但更硬的命题。
9. **查代码与产物，不只看论文**。附录里出现 `results/xxx/` 这类目录，说明组内有工程仓库；作者主页通常挂 GitHub handle；组织仓库列表能判断这个组有没有开源习惯。仓库在不在，直接决定主人能不能立刻开工——这件事比论文多写一节更重要。做法见 `references/code-availability-audit.md`。

## 流程

1. **落文本**：arXiv 走 e-print 源码（见 literature-verification）；非 arXiv 用 pdftotext，双栏排版会错位。
2. **读它自己声明什么**：引言看卖点，结论看它承认的局限与 future work——future work 里点名的方向往往就是主人想做的事。
3. **读附录**：系统提示的分节结构、必调 API、硬约束清单、设计守则（P1…Pn 这类）、solver 失败原因清单。
4. **建三层表**：层 | 内容 | 性质（算 / 学 / 已知约束）| 用什么。
5. **反推一个数**验证闭式性；顺带看约束值与参考值的比例是不是设计常数。
6. **列表达力边界与无信号失败**，各配一条原文依据。
7. **对撞想法**：找出主人想法落在哪一层、那一层的数学是什么、缺的是什么。只在他那一层里对话，不把它拖到别的层去讲。
8. **决定哪些话能写进对外文档**，不能写的要明说为什么不能写。
9. **查代码可用性**：按 `references/code-availability-audit.md` 走一遍。结论要写进交付物——有 / 没有 / 已有新仓库取代；它决定下一步能做什么，也决定索要什么。

## 陷阱

- **自己 pdftotext 的行号不是论文的出处**，别当引文坐标用。定位用章节、图表号、附录名。
- **同一篇里两处计数不一致时不许择一**（摘要 33 次与表格合计 36 次这类）。把矛盾本身写进结论。
- **「接口表达不了」与「物理上不可能」是两个命题**。前者关于语言，后者关于世界，要独立论证；且论证前提要覆盖全部情形（内力论证只在「全部接触都无外部支撑」时成立）。
- **「未记录某类失败」不等于「该类失败为零」**，只能说「没有该类实验的记录」。
- **缩写冲突**：SSM 在控制里是 state-space model，在深度学习里是 state-space sequence model（S4 / Mamba / DeltaNet），同词无关。跨领域转述前先钉住是哪一个。
- **「固定维」不等于「小维」**：DeltaNet 系的状态是 $d_k \times d_v$ 矩阵，百万量级，固定但做不了集合传播。
- **可达性要问清对象**：网络内部状态的集传播、输入集到输出集的界传播、输出参数空间的静态可行域、对象状态的 HJ 可达性——四件事四种数学，通常只有一个是你真需要的。集传播还多一层：状态映射可以是仿射，系数却依赖输入，所以精确传播只在输入固定时成立，输入一变就只能过近似。
- **文本输入是离散的，没有凸集可传**。要覆盖一类指令就枚举后逐点验证，别指望集合传播工具。
- **确定性不等于可逆，也不等于单射**；均值池化本身就是多对一。
- **编码器的两个空间分开写**：池化前的词级表示是 $n\times d$，随句子长度变；池化后的句子嵌入是 $d$，固定。说「嵌入空间维度 = 上下文长度 × 词数」会与「固定状态」自相矛盾；对外只报池化后的 $d$。
- **解码器可分析与否是设计决定的**：自回归出 token 基本不可分析；直接出低维参数加一个小的有限离散集就可以枚举。分析边界画在解码器上，不画在编码器上——编码器输入是离散序列，集合传播工具连输入集都定义不了；解码器输入是自己定义的连续凸集，分段线性时可逐区域精确求像。
- **图的视觉修辞会比正文多承诺**。流程图上一道竖线读起来像安全边界，正文可能没有对应的保证——发现自己别扭时，去正文找出它给这条边界的真实理由（往往与安全无关）。
- **字母表大小不是语言规模**：约束是「每时刻四种掩码之一」，不等于「整个模式序列只有四种」。序列空间是字母表的幂，先算指数再谈能不能枚举。
- **单点反推不是普查**：反推出两个数只证明那两个数是闭式的，不能说「几乎全部可闭式」。要讲比例就先数一遍。
- **写成「不得越界」的能力包线会变成钳制指令**：模型面对做不到的要求，最可能的行为是夹到上限，于是一个不可能的请求被静默实现成「最大值」——比报错更糟，因为它看起来像成功。
- **给论文作者的信里，每句话都要有主**：要么落在论文原话，要么落在主人原话；落不上的是你自己的评论，不进信。信里可以写主人的架构，但只能以他的原话、一小段、不编号的形式出现。见 `references/advisor-email.md`。
- **给一个问题命名之前先核术语血统**。术语可能是你想对立之物的子类（task identification 在机器人学里正是 system identification 的一支），也可能在目标圈里被读成相反方向（specification synthesis 常指「从规格合成控制器」）。没查过的名字不写进对外文档。
