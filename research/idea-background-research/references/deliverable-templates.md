# 落盘交付模板（文献库 / 可行性 / 实验设计）

用户明确要求「落盘 / 方便后续审阅」时按此组织；对话里只给压缩版结论。

## 0. 目录结构

```
调研根目录/
├── 环境报告_*.md            # 如涉及本机算力：实测（lscpu/free/df/rocm-smi/ps/ss），不凭记忆
├── <项目A>_绰名/
│   ├── literature_review/   # 逐篇文献文件（一 arXiv 号一文件）
│   │   └── README.md        # 索引
│   └── 提升方向与实验设计.md
└── <项目B>_绰名/ 同构
```

## 1. 逐篇文献文件 `literature_review/<arxiv>_<短名>.md`

1. 元数据表：arXiv 链接 | 发表 venue | 日期（含版本与 v2 改名注记）| 作者 | 类别 | 采集方式 + 全文缓存路径（`~/.hermes/cache/web/<file>`）。
2. **摘要（原文节选）**：blockquote，不转述——转述会引入自己的误读。
3. 关键发现：3-4 条 bullet，数字保真（倍数/百分比照抄原文）。
4. 与笔记的关系定位：一行角色标签（最近邻威胁 / 方法学基线 / 工具与框架 / 概念盟友…）+ 2-3 条「差异点必须钉死」或「可复用」。
5. 项目约束下的启示：1-2 条（资源、模型支持、可复现性）。

## 2. `literature_review/README.md` 索引

- 采集方式说明 + 项目核心命题重述 + 窗口状态（竞争者逼近程度）。
- 按角色分表：竞争者（威胁分级 ⚠ 标注）/ 方法学基线 / 工具与框架（或基准/度量/机制分类）。
- 结尾一段**独占缝隙声明**：枚举相邻文献各管什么，剩下没人管的就是本项目的位。

## 3. 可行性报告骨架（本机算力约束下）

- **约束 → 设计原则转化表**：每条硬约束一行（约束 | 强制推论），推论是设计动作不是抱怨。
- **路线矩阵**：路线 | 资源代价（实测数字）| 生产风险 | 裁决；裁决逻辑单独成段。核心手法是「科学问题与规模问题分离」——把动生产的路线拆出关键路径。
- **里程碑表**（周 | 交付 | 门槛）+ **风险清单**（每条含触发条件与对策；竞争者监控动作要具体到「每周扫什么」）。

## 4. 实验设计骨架

- 机制假设单句可证伪形式放最前（「X 随 Y 单调递增」式）。
- 编号实验（E0 先导 → P1 量化 → P2 主实验 → R 工程线），每个实验五件套：被试/数据/处理/任务、**成功门槛**（具体数字或统计标准）、协议纪律（每请求独立种子；判分器人工对齐 κ≥0.7；模板/格式控制防噪声）、资源与周期、**失败退路**（benchmark 短文 / 负结果附录 / 降级承重方向）。
- 报告格式引用现成 benchmark 协议（如 KV 复用类用「质量/计算/内存/延迟」四视角），判分用终态等价而非逐字比对。
- 里程碑含窗口倒计时：缝隙赛道按「最小可发表单元」排序，零生产风险的实验排最前。
