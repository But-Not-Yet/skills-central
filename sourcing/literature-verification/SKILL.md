# 文献引用核验纪律

适用：核验「支撑核心论断的文献数字/表述」，或批量精读文献入库。

## 触发场景

来自 2026-09-30 外部审查教训：声称核验了 16 篇但拿不出原文引证，被批「把结论当证据」。随后 pdftotext 删节又造成一次误判（CodeCRDT 数字，后对 e-print 源码翻案）。

## 铁律

1. **arXiv 论文核验一律走 LaTeX 源码**：`curl -sL https://arxiv.org/e-print/<id>` → tar 解包 → 直接 grep/read `.tex`。pdftotext 是付费墙/非 arXiv 的备用，不是首选。pdftotext 提取有删节（实测：CodeCRDT 2510.18893 的 pdftotext 输出漏掉摘要一半数字，导致一次「搜索摘要串台」误判，后对 e-print 源码翻案）。
2. **「我已核验」必须落成可核格式**：引用行 = 你的论断 + 原文逐字引文 + 出处定位（文件名/章节/行）。只有结论没有引文的核验 = 自证循环，会被再审打回。
3. **摘要级总结 ≠ 已核验**。批量入库的摘要级 md，其中支撑核心论断的数字要逐条升级到源码核验后才能进推演链。未升级的标「未核验」。
4. **「数字没被引用」≠「风险为零」**：被引为 ground truth 数据集/方法学锚点的文献，其方法节影响下游测量效度。实验设计前必须补读。
5. 精读 = 分段全文读（read_file 分页或源码分节），grep 只用于定位核验点，不用来拼读论文。
6. 「抓到错」本身是 claim：对文献的修正必须用最高等级媒介（arXiv=e-print 源码）逐字核验后才能宣布。不许边核验边宣布。实证教训：基于 pdftotext 删节文本 grep 做出的「串台」判定，被 e-print 源码翻案——原文两组数字都存在、层级不同。错的是核验媒介不是原文数字。
7. 核验汇报格式 = 论断 + 原文逐字引文 + 出处定位（文件/章节/行）。只有结论没有引文的核验＝自证循环，会被打回。

## 本地单篇精读的定位纪律

- **定位用章节、图表号、附录名，不用抽取文本的行号**。pdftotext（尤其双栏排版）的行号只在你自己的副本里成立，写进报告或对外文档会变成假坐标；引用格式仍是「论断 + 逐字引文 + 章节/图表定位」。
- **同一篇里两处计数不一致时不许择一**：摘要报 33 次、表格逐族合计 36 次这类矛盾，挑对自己有利的那个＝制造证据。把矛盾本身写进结论，并注明两个数各出现在哪个位置。
- **「未记录」不许升格为「零」**：全文搜不到某类失败结果（如 infeasible 的 run），只能写「没有该类实验的记录」。实验没做与实验证明为零是两件事。

## 转述传闻核验（别的模型/人转给的数字、会议、归属）

外部转述的文献论断按**字段独立核验**：数字、会议归属、机构归属、论文内容描述是四个独立字段。数字通常保真。归属与内容描述会走样（实测：论文内容被转成貌似合理的错误描述，机构归属无一手佐证）。任一字段核过不豁免其余字段。

- **标识符检索顺序**：先 arXiv API 标题检索（`curl -sL 'https://export.arxiv.org/api/query?search_query=ti:%22名称%22'`，快且免 key）。**同名撞车常见**——标题命中必须用摘要/主题确认是同一篇，撞名件连同编号写进文档防误引。
- **模型/论文名有多重别名**：架构键、社区服务名、官方报告标题常互不相同。官方报告标题往往不含架构代号——宣布「无官方报告/未搜到」前把每个别名分别检索一遍。漏一个别名就会把已存在的报告误判为缺失。
- **厂商博客是 JS 空壳**（web_extract 只回导航栏）时改走 HF 官方模型卡（自带架构参数表与基准表）或 arXiv HTML 全文 `https://arxiv.org/html/<id>v1`。
- **会议归属渠道**：OpenReview 直连（forum 与 api）常被 403 反爬 challenge 挡——ICLR/NeurIPS 走 proceedings.iclr.cc / proceedings.neurips.cc 正式条目或 iclr.cc virtual 页。ACL 走 aclanthology.org（自带 DOI 与页码）。期刊版常另存在（ACM DL 会议版+期刊版双记录），引用可升级期刊版。
- **预印本 PDF 抓取失败时**读 GitHub 仓库的 raw `.tex` 源文件（raw.githubusercontent.com）——那是 arXiv 投稿版一手摘要。
- **无出处的数字沿引用链反查**：搜数字原文+上下文，命中他篇引文行（常带图/表号）即定位一手出处。一手原文未开图则标「二手已核、一手待开」，不写「已核」。
- **分诊文档形状**：逐条一行（级别/用途/状态+标识符），状态只三档（已核/二手已核/待核）。附「核验方法记录」附录。每批核验后翻状态列并 git 提交一次。
- **同名概念先核对象身份再入相关工作**。转述来的概念若与自家项目概念同名而机制不同（如 diffusion LLM 的「KV 随去噪步漂移」vs 自回归管理操作导致的缓存损伤），分开定义、禁止焊死——写进文档的方法论警告节。
- **压缩摘要里的标识符按传闻级处理**：摘要会把同时段无关论文的 arXiv 编号卷进当前语境（把在谈的两篇与另一条线的编号混成一堆）。「那几篇」的编号先对 arXiv abs 页核身份再引用。只在对话粘贴文本里存在的论文（workshop 件、未公开稿）标「单一来源」，其数字与细节不进对外文本。

## 成书/非 arXiv 文献核验（全文副本 + pdftotext + 双向 grep）

要核的书没有 arXiv 源码时，别停在搜索摘要——把引用升级到一手全文：

1. **找全文**：archive.org 条目页直链 PDF（`curl -sL -A 'Mozilla/5.0' <item-url>/.../<book>.pdf`），或大学/机构站挂的 PDF。落地后 `pdftotext book.pdf book.txt`，存 scratch。
2. **定位**：对提取文本正则抓论断关键词的**全部**命中，逐条读上下文 ±300 字。只看第一条命中会读到删节版或另一处同名概念。
3. **同章反证 grep（防半句引用）**：核一个支持性数字时，必须在同一章再 grep 反向词——该论断的失败模式、恶化条件、例外、卡死/终结一类词。只引支持的那半句、漏掉同章推翻它的那半句，会被再审一击命中。支持性统计与其恶化条件常写在同一章相隔几页处。
4. **OCR 拼法如实登记**：提取件会把专名与作者名搅乱（如 "Clan Wile" 实为 Clancy Wile）。引事实、注明提取件里的拼法，不许静默改字。
5. **作者自述数字降级标注**：书里作者自报的准确率/成功率标「作者自述、独立复现未核」，除非另核到第三方复现或争议文献。

## 核验汇报的分级与顺序

- **逐条分级，禁全称盖章**：一手全文（带逐字引文）/ 摘要级 / 书目级（只核到标题年份出版社）/ 未核验 / 本轮未复验。一句「核心论断全部站住」＝自我盖章，必被打回。
- **先给人话结论，再给逐条台账**：汇报开头一句白话说清「结论站没站住、错在哪、错的是引用细节还是论点」，引用细节排在后面。引用密集当正文会换来「通俗讲解」的追问。
- 凭记忆写的引文标题、年份、页码是高危字段：标题记串（把同领域的他篇书评当原文）、年份说早（把平装版年当初版）都发生过。这三个字段必须逐条上网核，不许与内容一起「顺带核过」。

## 管线

- e-print 解包缓存放 scratch。核验结论连同逐字引文写进对应 literature/*.md 的核验注。
- 翻案要显式标注（「此前判定 X，源码核验后改为 Y，原因 Z」），不许静默改数。
