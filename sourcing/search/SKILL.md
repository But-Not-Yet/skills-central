# 上网取证的纪律

**适用**：任何「上网找资料 → 写进答复或文档」的活。`grounded-citations` 管引用的机械层（编号、Sources 块、逐字证据）。本技能管它上面一层：**找什么、信谁、什么能比**。两者叠加使用。

## When to Use

凡是要联网取资料、并把结果写进答复或文档时加载：模型/产品横向对比、
社区口碑与第三方基准调研、版本与价格核对、争议断言取证、以及任何会产出
带引用表格的调研。**只用内部知识就能回答、且不写进文档的对话，不必加载。**

## 防幻觉条款

- **不许编造工具没返回的东西**：没调过的工具、没读到的文件、没解析的 URL，一律不许写成已发生。
- **不许把记忆当检索结果**：数字、引文、判据、状态必须来自本次实际读到的原文。读不到就写「未核验」，不许用近似物顶替。
- **不许用「通常」「大概」掩盖空档**：不确定就说不确定，并给出可核验的下一步。
- **引用前先确认来源存在**：URL 要解析成功，模型/仓库要真实存在，页码/章节要对得上。
- **发现自己上一轮的说法与现在读到的不一致**：立刻说明冲突，以原文为准，不静默改口。

## 一条总纲

**搜索的可信度不取决于来源数量，取决于三条同时成立：实体身份锁死 + 来源分级 + 口径对齐。** 缺一条，后面的分析全建在沙上。

## 四条硬规则

1. **实体身份先行（identity before data）**。引用任何数字前，先写全它的实体全名与参数构成，例：`Qwen3.6-35B-A3B`（MoE，总参 35B / 激活 3B），而不是 `Qwen3.6`。**家族名不是实体**。同代不同档（27B 稠密 vs 35B-A3B MoE）不可互用数据。自查句：「我引的这个数是哪个模型、哪种参数构成、哪次评测跑的？」

2. **来源分级（provenance tier）**。每条数据打四档之一，**表格里必须有溯源列**：
   - **厂商自报**：官方模型卡、发布博客。宣传口径，默认最乐观。
   - **作者自报**：二创/衍生作者自跑的评测。看方法是否公开（判官、题量、生成长度、失败率）。
   - **第三方独立**：独立榜单、独立复现、取证站。
   - **聚合估算**：聚合站标 `Estimated` / `directional` 的行。**不构成胜负判定。**
   跨档不可直接比较。跨档并列时，结论必须显式降级为「有线索、未核验」。

3. **同口径才可比（same-harness or nothing）**。判官、题集、生成长度、上下文长度、量化档、harness，任一不同，两个数就**不可比**，只能各自陈述。典型陷阱：判官与题集都不同的拒绝率、思考预算撑大后失真的数学分、跨量化格式的 PPL。可比的通常只有三样：同一评测协议内的量、同一基准的共享行、同定义的 KL。

4. **主件优先（primary artifact beats reporting）**。能读主件就不读转述：`config.json` > 评测文章。原始 CSV / API > 榜单页面。`/raw/main/README.md` > 模型主页。`sitemap.xml` 枚举 > 站点印象。报道与主件冲突，**以主件为准，并在答复里说明冲突本身**。

## 三条流程纪律

5. **「有没有」由探测回答**。断言某站覆盖/未覆盖某物之前，必须先解析：`sitemap.xml` 枚举、API 查空、URL 404 探测。**禁止用印象代替调用。** 引用任何 URL 前先确认它解析（200）。

6. **取舍显式化**。收窄候选集时，**写明谁出局、依据是什么**。静默摘除等于漏报。

7. **去读作者自己的方法学批评**。一个会公开质疑同行数字不透明、并给出自己判官/题量/失败率的作者。其数字可信度显著高于只报一个漂亮分数的作者。这是最省力的可信度信号。

## 多轮检索的节奏

- **第 1 轮宽扫**：拿候选集与地图（榜单、每日发布流水、trending）。
- **第 2 轮追主件**：对每个候选直取 config / 权重 / README / 原始数据。
- **第 3 轮交叉验证**：找独立第三方，与自报数字对照，标注差异。
- **第 4 轮补缺口**：显式列出「找不到什么」，不用近似物填。

## 抓取战术（工具层）

- **HF**：`/raw/main/README.md` 绕开渲染。`/api/models?search=` 查存在性与元数据。`Range` 头可只取 safetensors 单张量字节，不必下整模型。`/api/collections/<user>/<slug>` 取集合清单。
- **站点覆盖**：`/sitemap.xml` 一次枚举全部路由，比翻页快且权威。用它回答「这站到底覆盖了什么」。
- **榜单/表格数据**：优先找它的 CSV / API 端点（如 HF Space 仓库里的 `*-data.csv`），别读渲染后的页面。
- **站点拦截**：换 UA、换抓取器（`web_extract` 失败则转 `terminal` + `curl`），仍失败转 `blocked-page-recovery`。
- **查论文用 arXiv 官方 API，不用通用网页搜索**：论文标题/编号丢进 web_search 返回全是域名与词典噪音。搜：`http://export.arxiv.org/api/query?search_query=all:%22精确短语%22&sortBy=relevance`（Atom XML，含标题/摘要/作者/编号，引号短语必须精确）。验号：`.../api/query?id_list=XXXX.XXXXX` 逐号确认存在与标题。**只引 API 返回过的编号**。API 查无（totalResults=0）就写「无法给出确切出处」，不许拿记忆里的编号充数。
- **同站多入口**：自称同类的站点可能是两家（例：`abliterlitics.dev` 与 `abliteration.org` 是不同的站，覆盖不同）。一个站没有不等于没有，**换站再查一轮**。

## 报告信号

- 表格缺**溯源列** = 该表不可用于决策。
- 出现「全面超越」「无损」而无方法学披露 = 按厂商自报处理，不可当结论。
- 同一页既有「共享行 A 赢」又有「聚合分 B 赢」 = **正常现象，差别在覆盖度**，要解释而不是择一。
- 自己写下「未核验」标记、下一轮又把它当已核 = 自强化环，必须回到原文。
- 数据表里出现与主线无关的实体名（家族名、同代他档）= 立刻停下核对身份。

## 常见失败模式

- **跨实体挪用**：把同代另一档（27B 稠密）的数字搬到目标（35B-A3B MoE）头上。
- **半份 config 下判定**：只读前几个键就断定架构（把 MLA 看成 MHA，KV 账差数倍）。
- **厂商表当事实**：自报「全面超越」未经第三方复核就进结论。
- **引用未解析 URL**：把没打开过的页面当覆盖证据。
- **静默摘除**：候选摘掉了却不声明原因。
- **混质同表**：厂商自报与第三方独立并列而不分层。
- **二手估算当数据**：站点给的推算值（如 KV 占用）与自己按主件算的结果冲突时，以主件为准。
