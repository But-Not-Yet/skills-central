# 读模型卡上的基准数字（可比性前置条件）

模型卡上的基准数不是「一个分数」，是「一次实验」。**比较前先把实验条件对齐**。对不齐就只能各自陈述，不能排名。

## 1. 协议身份是比数字的前提

同一名字的基准，底下可能是两套完全不同的做法，**系统性偏差不可忽略**：

- **lm-eval-harness 对数似然**：表头带 `Version / Filter / n-shot / Metric / Stderr`，值形如 `|acc |↑ |0.8372|± |0.0030|`。给选项打分取最高。
- **生成式（解析式）**：模型自己写出答案，再由提取器解析。**识别标志是「Parse failures: N」——对数似然根本不会有解析失败。**

生成式一般**偏低**（还要额外交解析失败）。**两套协议的数字不能同列排名。** 卡里没写协议时，从这些痕迹反推。反推不出来就标「协议未知」，不要当同把尺用。

## 2. 题量是覆盖率信号，不是装饰

很多基准的完整测试集题量是已知定值（MMLU 测试集 14,042 题）。卡里报的题数明显少于定值时，说明只跑了子集。**卡里通常不写为什么**。

做法：把「覆盖题量」当作一个字段记下来随数字一起报。跨卡比较时，题量不同就先标「覆盖不同」。**悄悄拿子集分去比全量分是错的。**

## 3. 微调/合并模型不继承底座的成绩（高频误判）

权重只要动过（SFT、merge、LoRA 合并），**底座的公开基准就不能拿来说这个微调版**。

- 血统对≠分数对。线性合并尤其容易让人误以为「还是原模型」。
- 作者自述「逻辑约等于原版」是**主观陈述**，不是 benchmark。可引用但必须标明是自述。
- 拿底座分填微调版的空格 = 跨实体挪用，宁可写「未测」。

## 4. 别跨尺寸聚合

一个家族名（如 `gemma-4`）下面常常同时有 2B / 4B / 12B / 26B-A4B / 31B。**对这个集合取中位数/均值，得到的数字不对应任何真实模型**。而且会静默地把某个尺寸的值标签成另一个尺寸的。

做法：先按**完整尺寸串**分桶（`26B-A4B` 与 `31B` 是两个模型），再各自聚合。每一行都绑死它自己的列名。家族级汇总只可用于「各尺寸都拿到相同值」的情形（同底座不同量化版共享同一组基准分就是典型）。

## 5. 厂商对照表：同表可比，但记下裁判是谁

某模型的卡里可能直接拿**竞品当列**，同一张表、同一套 harness。这种同表行行对照的**可比性远高于跨厂商拼表**，是能用的证据。

但要同时记下两件事：
- **裁判是竞争对手自己**（数字由该模型的作者跑出并发布），不是完全独立。
- 若某些行**在竞品自己发布的表里找不到**，几乎可以肯定那些行是该厂商自己跑的，不是转引。这一点反而提高了可比性，值得在结论里写明。

详尽的列位对齐陷阱见 SKILL.md 硬规则 7。

## 6. 缺口写「—」，并给覆盖率句

源数据里没有的字段**不能留空**（会被读成 0），也**不能从兄弟型号借**。写「—」，并单独一句说明「共 X/Y 个源携带该字段」。

## 输出

表：`模型 | 基准 | 值 | 协议 | 覆盖题量 | 来源档位`。缺协议或缺题量的行，同列比较前先标「不可比」。
