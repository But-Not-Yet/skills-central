## When to Use

`engineering-vs-research-mode` 把项目判定为**工程**物种后，本 skill 提供完整的工程流程（八站）。写任务书、排期、或中途迷失方向时回到这里对流程。

# 工程项目全流程（八站）

工程的目标函数 = 在约束内交付主人真正需要的改变。不是「做出来」，是「主人用起来且没坏事」。

## 站 1：需求（needs ≠ wants）

主人说的通常是 wants（「加个存根层」），需求是背后的痛点（「长会话变卡/变贵」）。开工前用一句话复述：「我理解要解决的问题是 X，成功的样子是 Y，对吗？」只此一句，不发问卷。ENGR 1182 级别的核心训练就是这个：先把 needs 和 spec 分开。
- 主人的既有习惯即依据：他动文档前先要「修改大纲+理由+引用资料」，那就是他验收需求理解的方式。

## 站 2：规格与验收标准（先写死后动工）

- 验收标准 = 行为清单：装得上、不坏事、可回滚、主人用着没觉得差。**不写改善幅度百分比**（那是科研判据，见总纲）。
- 明确非目标（out of scope）清单，和验收同等重要，防止范围蔓延。
- 禁用开关在设计里预留，不是事后补。

## 站 3：方案选择（含「不做」这个备选）

- 永远把 **do-nothing（维持现状）** 列为第一个备选再比较。改动有隐性成本（复杂度、维护、认知负担），收益必须赢过它。
- 工程经济学心算版（ESD.70J 的轻量应用，不必真建 NPV 表）：这个改动的价值是否随使用持续产生？一次性的漂亮 vs 天天用的顺手，选后者。维护成本计入总成本：写得快不等于成本低，留下的代码才是负债。
- 多方案时呈给主人「选项+代价+建议」，他拍板。技术栈已锁定就不重开。
- **升级项标注来源**：排期表每条写「症状驱动 / 架构欠账 / 工程地基」。症状驱动的项必须对应一条可复现的错误；架构欠账与工程地基单独成组，不许混在「针对今天的问题」里。主人会追问来源，混着说会被打回。

## 站 4：实现（最小正确增量）

- 按验收标准倒排任务，每块可独立测试。YAGNI：调研差距清单 ≠ 实现承诺。
- 不确定处先查文档/源码再动手（主人纪律），不凭记忆。

## 站 5：验证（对着站 2 打，不自加考题）

- 测试证明的是**验收标准**，不是「再多测一点」。测完逐条勾验收清单，没勾上的不算完。
- 同一失败修两轮不收敛 → 停，问主人。第三轮自嗨是工程事故。
- **测试三档经济学（2026-10-24 主人裁定：资源受限，功能开发走『实现→重启→看疗效→不行再修』）**：
  1. **留（便宜保险）**：交卷前跑一遍既有测试套件防改坏旧功能——存量套件是已付过钱的资产，本机 564 用例 72 秒。只此一跑，不许多。
  2. **砍（贵的主要开销）**：新功能先写 RED 测试、为每个新功能配 pytest 堆＋变异负对照——这是论文腔，卡体别再要求。功能验收改用活体探针：重启后按探针清单看真行为。
  3. **例外（窄）**：纯算法件的正则/账本格式类改动配 3-5 行钉测试——这类 bug 是静默数据损坏（正则几十轮才响一次、账本每轮只写一行），重启看疗效抓不住。哈希闸、Verdict 格式属此族；卡片渲染、注入节奏属第 2 档。
- 卡体验收标准写法随之改：不写「N tests + M 变异对照」，写「既有套件全绿＋活体探针清单」。

## 站 6：交付与回滚

- 交付物 = 能用的东西 + 一行回滚方法。回滚必须实测过（改回去、确认一切照旧），没测过的回滚不算存在。
- 发布物（README/许可）按需最小，不为仪式感加层。

## 站 7：反馈回路（工程的「测量」就是这里）

- 主人日常使用 = 第一测量仪。交付时明确告诉他裁决方式：「不好用说一声，一行配置就关掉。」
- 反馈 → 修改或禁用，这就是完整回路。**不因为反馈没给数字就补建仪器**，那是物种漂移。

## 站 8：交付完成后的复盘

- 进度文件逐站一行状态+证据指针（给执行者自己留的 durable 记录，不为对话重复建报告层）。
- 复盘三问：哪站跳过了？哪站过度了？下次同类项目最短路径是什么？教训写进本 skill，不写进记忆。

## 柔性设计原则（贯穿各站）

ESD.71 的核心：未来必然不确定，好设计在整个场景范围内交付价值。工程版落地 = 每个决策尽量保留可逆性（配置开关、附加式改动、不动核心）。不可逆的改动（改数据格式、删功能）要单独向主人要授权。柔性不是多写代码，是把「以后能改」设计进去。
