# 独立架构页/状态页更新

## When to Use

用户要更新独立的架构图/状态页（不是聊天内嵌卡），尤其是把旧快照换成当前看板状态、统计待办、补两线编排时。

## 工序

1. **旧页只是快照，不是事实源。** 先读旧 HTML，用 `search_files` 查旧状态、旧“截至”、旧 TODO。把旧页的 `planned/running/done` 一律当历史。
2. **取活体并定义计数口径。** `date`；`hermes kanban --board <slug> list --json`。当前 board 的卡与旧 default board 的归档 done 行分开算；表里可以列历史 done，但计数框只算当前 board。新建/新解阻的卡要同步加行并改计数。
3. **备份后改。** `cp file file.bak-<timestamp>`；替换 TODO `<tbody>` 前断言 `<tbody>` 唯一；状态块逐个 patch。标题时间戳用当前 `date`，禁止写未来时间。
4. **加编排区时保持单一事实源。** 用户要两线/排期时，Markdown 编排文件放完整表；HTML 只放摘要和指针，避免两处状态漂移。
5. **验收。**
   - `python3` 的 `html.parser` 跑一遍，标签栈无未闭合；
   - 用 `search_files` 查旧状态/旧时间应为 0；
   - 表内计数、标题计数、活体 `list --json` 三处相等；
   - 备份存在；新卡已进表；没有未来时间戳。

## 常见坑

- 把旧页的 done 行当当前 board 计数，或把旧 default board 的完成项漏掉，导致“看板总数”和表里行数对不上。
- `tbody` 不是唯一时直接 `replace`，会改错表；先断言。
- 状态块只改文字不改 chip class，颜色仍停在旧状态；两者一起改。
- 旧页的“截至”时间留在顶部，读者会当现行；每次更新都要刷新。
- 用户要“还有多少待办”时，给三层数：当前 board 总数/按状态、去掉永久/插件外后的可执行数、按线剩余数。不要让一个总数包打天下。
