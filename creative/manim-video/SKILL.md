# Manim 视频制作流水线

## 何时使用

当用户要求：动态讲解、数学动画、概念可视化、算法逐步演示、技术科普、3Blue1Brown 风格视频，或任何带几何 / 数学内容的程序化动画时使用。用 Manim Community Edition 制作 3Blue1Brown 风格科普视频、算法可视化、方程推导、架构图与数据故事。

## 创作标准

这是教育电影。每一帧都在教学。每个动画都揭示结构。

**在写下第一行代码之前**，先明确叙事弧线。它纠正了什么误解？「顿悟时刻」是什么？怎样的视觉故事把观者从困惑带到理解？用户的提示词只是起点——要以教学野心去诠释。

**几何先于代数。** 先展示形状，再展示方程。视觉记忆比符号记忆编码更快。当观者在公式之前先看到几何图案，方程就显得理所当然。

**首次渲染即达到优秀，不可妥协。** 输出必须视觉清晰、美学统一，无需多轮返工。若看起来杂乱、节奏不佳，或像「AI 生成的幻灯片」，那就是错的。

**不透明度分层引导注意力。** 绝不要把所有东西都以全亮度展示。主要元素 1.0，语境元素 0.4，结构元素（坐标轴、网格）0.15。大脑分层处理视觉显著性。

**留白呼吸。** 每个动画之后都需要 `self.wait()`。观者需要时间吸收刚出现的内容。绝不从一段动画急匆匆切到下一段。关键揭示后停 2 秒绝不浪费。

**统一的视觉语言。** 所有场景共享同一调色板、一致的字体尺寸、匹配的动画速度。一段技术上正确、但每个场景都用随机不同颜色的视频，是美学上的失败。

## 前置条件

运行 `scripts/setup.sh` 校验所有依赖。需要：Python 3.10+、Manim Community Edition v0.20+（`pip install manim`）、LaTeX（Linux 上 `texlive-full`，macOS 上 `mactex`）以及 ffmpeg。参考文档针对 Manim CE v0.20.1 测试。

## 技术栈

每个项目一个 Python 脚本。无需浏览器、Node.js 或 GPU。

| 层 | 工具 | 用途 |
|-------|------|---------|
| 核心 | Manim Community Edition | 场景渲染、动画引擎 |
| 数学 | LaTeX (texlive/MiKTeX) | 通过 `MathTex` 渲染方程 |
| 视频 I/O | ffmpeg | 场景拼接、格式转换、音频封装 |
| TTS | ElevenLabs / Qwen3-TTS（可选） | 旁白配音 |

## 流水线

```
PLAN --> CODE --> RENDER --> STITCH --> AUDIO (optional) --> REVIEW
```

1. **PLAN** —— 写 `plan.md`，含叙事弧线、场景列表、视觉元素、调色板、配音脚本
2. **CODE** —— 写 `script.py`，每个场景一个类，各自可独立渲染
3. **RENDER** —— 草稿用 `manim -ql script.py Scene1 Scene2 ...`，成品用 `-qh`
4. **STITCH** —— 用 ffmpeg concat 把场景片段拼成 `final.mp4`
5. **AUDIO**（可选）—— 通过 ffmpeg 加入旁白和 / 或背景音乐。见 `references/rendering.md`
6. **REVIEW** —— 渲染预览静帧，对照 plan 校验，调整

## 项目结构

```
project-name/
  plan.md                # Narrative arc, scene breakdown
  script.py              # All scenes in one file
  concat.txt             # ffmpeg scene list
  final.mp4              # Stitched output
  media/                 # Auto-generated by Manim
    videos/script/480p15/
```

### 动画速度

| 场景 | run_time | 之后 self.wait() |
|---------|----------|-------------------|
| 标题 / 开场出现 | 1.5s | 1.0s |
| 关键方程揭示 | 2.0s | 2.0s |
| 变换 / 变形 | 1.5s | 1.5s |
| 辅助标签 | 0.8s | 0.5s |
| FadeOut 清理 | 0.5s | 0.3s |
| 「顿悟时刻」揭示 | 2.5s | 3.0s |

### 字体层级

| 角色 | 字号 | 用途 |
|------|-----------|-------|
| Title | 48 | 场景标题、开场文字 |
| Heading | 36 | 场景内的章节标题 |
| Body | 30 | 讲解文字 |
| Label | 24 | 注释、坐标轴标签 |
| Caption | 20 | 字幕、小字 |

### 字体

**所有文字都用等宽字体。** Manim 的 Pango 渲染器在各种字号下对比例字体都会产生错误的字距。完整建议见 `references/visual-design.md`。

```python
MONO = "Menlo"  # define once at top of file

Text("Fourier Series", font_size=48, font=MONO, weight=BOLD)  # titles
Text("n=1: sin(x)", font_size=20, font=MONO)                  # labels
MathTex(r"\nabla L")                                            # math (uses LaTeX)
```

可读性下限 `font_size=18`。

### 逐场景变化

绝不对所有场景用相同配置。对每个场景：
- 从调色板中选**不同的主色**
- **不同的布局**——不要总把所有东西居中
- **不同的动画入场**——在 Write、FadeIn、GrowFromCenter、Create 之间变化
- **不同的视觉分量**——有些场景密集，有些疏朗

## 工作流

### 第 1 步：规划（plan.md）

写任何代码之前，先写 `plan.md`。完整模板见 `references/scene-planning.md`。

### 第 2 步：写代码（script.py）

每个场景一个类。每个场景都可独立渲染。

```python
from manim import *

BG = "#1C1C1C"
PRIMARY = "#58C4DD"
SECONDARY = "#83C167"
ACCENT = "#FFFF00"
MONO = "Menlo"

class Scene1_Introduction(Scene):
    def construct(self):
        self.camera.background_color = BG
        title = Text("Why Does This Work?", font_size=48, color=PRIMARY, weight=BOLD, font=MONO)
        self.add_subcaption("Why does this work?", duration=2)
        self.play(Write(title), run_time=1.5)
        self.wait(1.0)
        self.play(FadeOut(title), run_time=0.5)
```

关键模式：
- 每个动画都加**字幕**：`self.add_subcaption("text", duration=N)` 或在 `self.play()` 上写 `subcaption="text"`
- 文件顶部放**共享颜色常量**，保证跨场景一致
- 每个场景都设置 **`self.camera.background_color`**
- **干净退出**——场景结束时 FadeOut 所有 mobject：`self.play(FadeOut(Group(*self.mobjects)))`

### 第 3 步：渲染

```bash
manim -ql script.py Scene1_Introduction Scene2_CoreConcept  # draft
manim -qh script.py Scene1_Introduction Scene2_CoreConcept  # production
```

### 第 4 步：拼接

```bash
cat > concat.txt << 'EOF'
file 'media/videos/script/480p15/Scene1_Introduction.mp4'
file 'media/videos/script/480p15/Scene2_CoreConcept.mp4'
EOF
ffmpeg -y -f concat -safe 0 -i concat.txt -c copy final.mp4
```

### 第 5 步：审查

```bash
manim -ql --format=png -s script.py Scene2_CoreConcept  # preview still
```

## 关键实现要点

### LaTeX 用原始字符串
```python
# WRONG: MathTex("\frac{1}{2}")
# RIGHT:
MathTex(r"\frac{1}{2}")
```

### 贴边文字 buff >= 0.5
```python
label.to_edge(DOWN, buff=0.5)  # never < 0.5
```

### 替换文字前先 FadeOut
```python
self.play(ReplacementTransform(note1, note2))  # not Write(note2) on top
```

### 绝不动画未添加的 mobject
```python
self.play(Create(circle))  # must add first
self.play(circle.animate.set_color(RED))  # then animate
```

## 创作发散（仅在用户要求实验性 / 创意 / 独特输出时使用）

若用户要求创意、实验或不循常规的讲解方式，选择一种策略并在设计动画*之前*推演它。

- **SCAMPER** —— 当用户想要对标准讲解来一次全新诠释
- **假设反转（Assumption Reversal）** —— 当用户想挑战某个东西通常是怎么教的

### SCAMPER 变换
拿一个标准的数学 / 技术可视化并改造它：
- **Substitute（替换）**：替换标准的视觉隐喻（数轴 → 蜿蜒路径，矩阵 → 城市网格）
- **Combine（组合）**：融合两种讲解方式（代数 + 几何同时进行）
- **Reverse（反转）**：逆向推导——从结果出发反推到公理
- **Modify（修改）**：夸大某个参数以展示它为何重要（学习率放大 10 倍、样本量放大 1000 倍）
- **Eliminate（消除）**：去掉所有记号——纯粹用动画与空间关系来解释

### 假设反转
1. 列出这个主题在可视化上的「标准」之处（从左到右、2D、离散步骤、正式记号）
2. 挑出最根本的假设
3. 反转它（从右到左推导、把 2D 概念做 3D 嵌入、用连续变形代替分步、零记号）
4. 探索反转揭示了哪些标准做法所隐藏的东西
